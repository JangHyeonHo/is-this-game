# 04. 게임 디자인 문서

작성: 2026-07 · 상태: **초안 (M1 프로토타입으로 검증 예정)**

---

## 1. 컨셉

> **판타지 길드를 운영하며 모험가를 한 명씩 짧게 육성하고,
> 그들로 파티를 짜서 의뢰에 내보내는 게임.**

**한 줄 훅:** 모험가는 스스로 싸운다. 당신이 키운 만큼만.

**장르 태그:** Management, Party-Based RPG, Roguelite, Auto Battler, Character Training

**비교 대상 (플레이어에게 설명할 때):**
"우마무스메의 육성 사이클 + Battle Brothers의 용병단 운영 + 파이널 판타지 12의 감빗"

---

## 2. 3층 루프 구조

```
┌─ 길드 층 (수십 시간, 세이브 단위) ──────────────────────┐
│  재정 · 평판 · 시설 · 경쟁 길드 · 시즌 진행              │
│                                                          │
│  ┌─ 모험가 층 (30~40분, 반복 단위) ─────────────────┐   │
│  │  영입 → 육성 런 → 은퇴/사망                       │   │
│  │                                                    │   │
│  │  ┌─ 전투 층 (2~5분) ──────────────────────────┐   │   │
│  │  │  파티 편성 → 자동 전투 + 제한된 개입        │   │   │
│  │  └─────────────────────────────────────────────┘   │   │
│  └────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────┘
```

**각 층이 존재하는 이유:**

| 층 | 플레이어에게 주는 것 | 개발 관점의 이유 |
|---|---|---|
| 전투 | 즉각적 피드백, "내 빌드가 통했다" | 자동 기반이라 조작 UI·애니메이션 요구가 낮음 |
| 모험가 | 애착, 반복 가능한 세션, 실험 | **루프 하나만 잘 만들면 콘텐츠로 불릴 수 있음.** 데모 = 육성 런 1회 |
| 길드 | 장기 목표, 러닝타임 | 콘텐츠 재사용으로 플레이 시간 확보. 환불률 방어 |

## 3. 모험가

### 3.1 표현 방식 — 레이어 조합형 초상화

Battle Brothers 방식. 파츠를 레이어로 겹쳐 조합합니다.

```
[배경] → [체형] → [피부/종족] → [얼굴] → [머리] → [수염] → [흉터] → [장비] → [상태 오버레이]
```

**설계 원칙: 아트가 곧 시뮬레이션 상태의 표현이 된다.**

- 부상을 입으면 흉터 레이어가 **영구히** 붙는다
- 나이를 먹으면 머리색이 변한다
- 장비를 바꾸면 초상화에 반영된다
- 사기·부상 상태가 오버레이로 드러난다

파츠 세트 한 벌(예산 10~15만원)로 수천 명의 고유한 모험가를 생성할 수 있고,
**추가 아트 비용 없이 캐릭터가 "변화"합니다.**

### 3.2 애착은 그림이 아니라 기억에서 나온다

이 게임의 핵심 가설입니다. 검증된 선례가 있습니다.

| 게임 | 아트 수준 | 애착의 근원 |
|---|---|---|
| RimWorld | 졸라맨 | 관계 · 트라우마 · 과거사 |
| Dwarf Fortress | ASCII | 생성된 역사 |
| Battle Brothers | 레이어 조합 초상화 | 출신 · 생존한 전투 · 부상 이력 |

따라서 **모든 모험가는 이력(Chronicle)을 누적**합니다.

```
아스카르 (37세, 몰락 귀족 출신)
  · 첫 의뢰에서 동료 미렌을 잃음        → [죄책감] 특성 획득
  · 늑대굴 소탕 3회 성공                → [야수 사냥꾼] 특성
  · 왼팔 부상 (영구)                    → 근력 -15, 흉터 레이어
  · 신입 3명을 훈련시킴                 → [멘토] 특성
  · 은퇴: 42세, 길드 훈련교관으로 전직  → 이후 신입 육성에 보너스
```

은퇴한 모험가가 사라지지 않고 길드에 남는 것이 중요합니다.
**손실이 자산으로 전환되면 애착이 시스템적으로 보상됩니다.**

### 3.3 스탯 설계

일반 능력치 외에, 이 게임의 핵심 스탯이 하나 더 있습니다.

| 분류 | 스탯 |
|---|---|
| 신체 | 근력 · 민첩 · 체력 |
| 정신 | 의지 · 지식 |
| **판단력 (Judgement)** | **전투 중 AI가 얼마나 좋은 선택을 하는지** ← 이 게임의 중심 스탯 |
| 사회 | 평판 · 충성도 |

**판단력이 왜 중심인가는 4장에서 설명합니다.**

## 4. 전투 — 감빗 + 판단력 모델

> **전투는 자동으로 진행된다. 다만 캐릭터가 얼마나 똑똑하게 싸우는지는
> 육성으로 얻은 판단력과 플레이어가 편성한 전술 규칙이 결정한다.**

### 4.1 전술 규칙 (Tactic)

FF12 감빗과 유사한 조건-행동 규칙입니다. 위에서부터 순서대로 평가합니다.

```
1. [아군 HP < 30%]          → 회복약 사용
2. [적이 시전 중]            → 차단
3. [적 후위가 노출됨]        → 돌격
4. (기본)                    → 가장 가까운 적 공격
```

**규칙 슬롯은 육성으로 늘어나고, 규칙 자체도 육성으로 배웁니다.**
신입은 슬롯 2개에 기본 규칙만 갖고, 베테랑은 슬롯 6개에 정교한 규칙을 갖습니다.

### 4.2 판단력 = AI 품질

여기가 이 설계의 핵심입니다. **판단력 스탯이 AI의 실행 품질을 좌우합니다.**

| 판단력 | 전투 중 행동 |
|---|---|
| 낮음 | 규칙을 자주 무시한다. 위험할 때 후퇴하지 않고, 회복약을 아끼다 죽는다. 타겟 선택이 나쁘다 |
| 보통 | 규칙대로 움직인다 |
| 높음 | 규칙에 없는 상황도 스스로 잘 판단한다 (Utility AI의 가중치가 정확해짐) |

구현상으로는 **Utility AI의 점수 계산에 판단력이 개입**합니다.
판단력이 낮으면 점수에 노이즈가 끼거나 근시안적 평가(다음 1턴만 봄)를 하고,
높으면 정확하고 멀리 봅니다.

### 4.3 플레이어의 개입

전투당 제한된 **지휘 포인트(Command Point)** 를 씁니다.

| 개입 | 비용 |
|---|---|
| 특정 캐릭터에게 즉시 행동 지시 | 1 |
| 집중 타겟 지정 (파티 전체) | 1 |
| 후퇴 / 대형 변경 | 2 |
| 규칙 일시 무시하고 직접 조작 (1턴) | 2 |

**개입권이 제한적이라 "언제 쓸까"가 매 전투의 판단 재미가 됩니다.**
그리고 잘 키운 파티일수록 개입할 일이 없어지므로, **육성의 보상이 즉각적으로 체감됩니다.**

### 4.4 이 설계가 동시에 푸는 문제들

| 문제 | 해결 |
|---|---|
| "조작이 아예 없으면 심심하다" | 지휘 포인트 개입 |
| "육성의 결과가 안 보인다" | 판단력이 곧 전투 품질. 잘 키우면 눈에 띄게 잘 싸운다 |
| 1인 개발의 전투 개발 비용 | 자동 기반 → 조작 UI·애니메이션 요구 낮음. 배속/스킵 가능 |
| 기술적 도전을 하고 싶다 | **GOAP/Utility AI가 백엔드 기술이 아니라 플레이어가 직접 만지는 시스템이 됨** |
| "파티 구성이 메인" | 캐릭터 조합 + 전술 규칙 조합 = 빌드. 자동 전투가 그 빌드를 검증 |

## 5. 육성 런

**길이:** 12~20턴 / 실시간 30~40분

**턴마다 하는 일:** 훈련 / 실전 의뢰 / 휴식 / 교류 중 선택.
자원(체력·사기·자금·시간)이 서로 경쟁하게 만들어 매 턴이 선택이 되게 합니다.

**중간에 이벤트가 끼어듭니다.** 절차적으로 생성되며, 캐릭터의 특성·이력·관계에 반응합니다.
[죄책감] 특성이 있는 캐릭터는 다른 이벤트를 만납니다.

**런 종료 조건:** 계약 기간 만료, 사망, 은퇴, 이적.

> **설계 주의:** 육성 런이 "최적해를 외우면 끝나는 퍼즐"이 되면 반복 가치가 사라집니다.
> 무작위 이벤트와 캐릭터별 초기 조건 차이로 매번 다른 판단을 요구해야 합니다.
> **M1에서 반드시 검증할 항목입니다.**

## 6. 길드 층

| 시스템 | 내용 | 우선순위 |
|---|---|---|
| 재정 | 급여, 장비, 시설 유지비 vs 의뢰 보상 | **필수** |
| 의뢰 | 절차적 생성. 난이도·보상·평판 영향 | **필수** |
| 평판 | 받을 수 있는 의뢰의 질을 좌우 | **필수** |
| 시설 | 훈련장, 숙소, 대장간 — 육성 런에 영향 | 중요 |
| 은퇴자 | 교관·상인 등으로 전직해 길드에 기여 | 중요 |
| 경쟁 길드 | AI 길드가 의뢰를 가로챔 | 있으면 좋음 |
| 시즌/연간 목표 | 장기 압박 | 있으면 좋음 |

## 7. 기술적 도전이 게임 디자인과 만나는 지점

목적 3번(기술적 도전)이 게임 재미와 분리되지 않도록 배치했습니다.

| 기술 | 게임 내 역할 |
|---|---|
| **Utility AI** | 전투 중 캐릭터 판단. 판단력 스탯이 파라미터로 개입 |
| **GOAP** | 파티 단위 전술 목표 수립 (돌파 / 방어 / 후퇴) |
| **Behavior Tree** | 수립된 목표의 실행 |
| **절차적 생성** | 모험가 생성, 이벤트, 의뢰, 던전 배치 |
| **시뮬레이션** | 길드 경제, 평판, 경쟁 길드 |
| **결정론적 RNG** | 시드 기반 재현. 밸런스 회귀 테스트와 배치 시뮬레이션의 전제 |

**결정론적 RNG는 선택이 아니라 필수입니다.**
자동 전투 게임의 밸런싱은 "10,000회 시뮬레이션 돌려 승률 분포 보기"로 하는데,
이게 되려면 재현 가능해야 하고, 그러면 AI 에이전트가 밤새 밸런스 통계를 뽑을 수 있습니다.

## 8. 미결정 항목

M1 프로토타입으로 검증한 뒤 결정합니다.

- [ ] 육성 런 길이 (12턴 vs 20턴) — 실제로 돌려보고 결정
- [ ] 파티 규모 (3인 / 4인 / 6인)
- [ ] 전투가 그리드 기반인가, 전열/후열 추상화인가
- [ ] 모험가 영구 사망 여부 (로그라이트 강도)
- [ ] 게임 제목
- [ ] 엔진 (Unity vs Godot) — [adr/0001](adr/0001-engine-agnostic-core.md) 참조. **M1 이후 결정**
