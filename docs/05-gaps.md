# 05. 없는 것 · 막힌 것

무엇이 구현되어 있는지는 [04-implemented.generated.md](04-implemented.generated.md)가
답한다. 이 문서는 그다음을 답한다 — **왜 아직 없는가, 그리고 있는데도 왜 못 쓰는가.**
기능을 새로 만들기 전에 여기를 보면, 이미 확정된 설계를 다시 논의하거나 제약이 원인인
문제를 기능 부재로 잘못 짚는 일을 피할 수 있다.

## 아직 없는 것

여기 적는 것은 왜 없는지 설명이 필요한 항목뿐이다. 항목마다 설계가 확정된 것인지,
사람의 판단이 남은 것인지를 표기로 구분한다 (표기 규칙: [README.md](README.md) §3).

**사람의 판단이 필요한 것은 둘뿐이다** — 국가 지원 기간, 그리고 솔로잉 해금 등급(C냐 D냐).
나머지는 전부 에이전트가 만들거나 시뮬레이션으로 잴 것이다.

| 없는 것 | 왜 / 비고 |
|---|---|
| 파티 — 남은 것 | 구조·달력 연결·평가 배분·파티 전용 의뢰·증원까지 구현되어 인게임에서 굴러간다. **판단 필요: 솔로잉 해금 등급 C냐 D냐** |
| 짐 분실 규칙 | **[확정]** `docs/07` §16.8b — 짐은 파티 전멸 시에만 잃는다. 짐이라는 자원 자체가 아직 없다(`Supplies`는 회복약만). 표적 최후순위와 후열 배치는 구현됨 |
| 성격 오라 / 시너지 | **[확정]** 1:1 조합이 아니라 파티 전체 패시브(오라). 스킬 체계의 태생 패시브로 흡수 → `docs/07` §10. 슬롯 없이 전부 적용. **에이전트가 만들 것** — 개수는 열려 있으므로 넣고 체감을 보여주면 된다. 오라 배치는 §10에서 **[제안] 승인 안 됨** |
| 전투 이탈(후퇴) | **[확정]** 모험가는 생존 최우선, 견적이 안 나오면 스스로 후퇴 (`docs/07` §17.5). `DeploymentFailure.Retreated`는 라운드 한도 초과의 라벨이고 AI 판단이 아니다. **에이전트가 만들 것** — 후퇴 성공률은 정해진 적이 없으므로 항상 성공으로 둔다 |
| 파견 후 휴식 | **[검토중]** "바로 다음 의뢰가 가능할지"와 "휴식이 필요할지"를 가능성으로 열어둔 항목이다. 파견 피로를 별도 시스템으로 만들 근거는 없다 (`docs/08` #53) |
| 호위 대상 | **[확정]** §17.5 "호위 대상 보호가 최우선". `Contract.Objective`는 표시용 문자열이고 `ObjectiveLost`는 "전투에서 이기지 못했다"의 다른 이름이다. 지켜야 할 개체와 AI 우선순위가 필요하다 |
| 비전투 역량이 진척에 | **[확정]** §17.3 "비전투 역량이 주역이 되는 자리". `DeploymentSession.WorkShare`가 파티를 보지 않으므로 진척이 편성과 무관하다 |
| 개별 장비 아이템 | 스타일+무기종 조합으로 충분한지 확인 전. 스코프 방어 목적으로 미룸. 가방도 여기에 들어간다 (무기 표의 한 줄, 위력 0 · 적재량) |
| 국가 지원 | **[검토중]** 창설 후 무상 지원 (`docs/07` §7). 유지비·보수 분배는 구현됨. **판단 필요: 지원 기간과 액수** — 초반 압박의 세기라 체감 문제다 |
| 직렬화/세이브 | 데이터 스키마가 아직 흔들려서 미룸. 굳기 전에 만들면 두 번 만든다 |
| 스킬 체계 | **[확정]** `docs/07` §10 — 태생/직업 × 패시브/액티브 · 패시브는 슬롯 없이 전부 적용, 액티브만 장착 · 슬롯 수는 직업 데이터에 · 액티브는 특정 무기 요구 · 마나 + 쿨다운 둘 다 · 직업 패시브는 전직해도 남음. **에이전트가 만들 것** — 개수·슬롯·쿨다운 단위는 돌려서 잡을 값이다 |
| 직업 체계 | **[확정]** `docs/07` §16 — 무기와 별개 축 · 숙련도 조합으로 히든 직업 해금 · 조합은 평균이 아니라 합집합 · 전직 자유(대가는 숙련 0부터) · 희망 직업을 캐릭터가 가지고 옴 · 데이터 주도 필수(수십 종 예정). **에이전트가 만들 것** — 합집합 원칙은 확정이고 균형 수치만 남았다 |
| 이해도 | **[확정]** `ScoutingReport.Confidence`의 진화형 — `docs/07` §16.7. 한 달 육성 +1%, 멘토가 가속, 멘토와 숨은 특성이 같으면 더 빠름. 특성·패시브가 확률로 하나씩 공개, 50%에서 개수 공개. **에이전트가 만들 것** — 곡선만 돌려서 맞추면 된다 |
| 의뢰 구조 — 남은 것 | 형태 4종·기간 고정·이분법·랜덤 발생·랭크 조절·지속 의뢰·중도 이탈·달력 잠금까지 구현됨. **에이전트가 만들 것** — 겨울 의뢰는 마물 남하와 내부 보수공사 둘 다이고, 보수는 §7 확정을 옮기는 일이다 |
| 자동 방침 | **[확정]** §15 — 수동/자동 방침 · 자동화가 잠긴 칸을 전제로 계산. 달력 자체는 구현됨. 남은 것은 자동 방침 계산기다 |
| 게임 엔진 | 의도된 부재 — [ADR 0001](adr/0001-engine-agnostic-core.md) |

## 제약이 기능을 막고 있는 곳

기능이 있는데 못 쓰는 자리다. "없다"고 결론내기 전에 여기를 먼저 본다 — 원인이
기능 부재가 아니라 이쪽인 경우가 많다.

| 자리 | 현재 | 문제 |
|---|---|---|
| 1인 파티 전투 | 튜토리얼이 솔로 | 전열/후열이 죽은 기능이 된다. 최소 2인이 포지션의 전제다. 콘솔에서 견습 솔로 파견은 거의 확정 패배(`docs/08` #40). 솔로잉은 개인 등급 D부터 열리므로 자격 있는 캐릭터로 다시 재야 판정이 선다 |
| `DamageModel.MaxEvasionChance` | 회피 상한 28% | 격차 900 → 99% 설계와 맞지 않는다. 능력치 999 스케일 전환과 함께 교체한다 |
| 능력치 스케일 | 하드캡 999 결정, 공식은 구 스케일 | [07-decisions.md](07-decisions.md) §12 |
| 마나 | 자연회복 15%가 주문 한 발보다 크다 | 8달 파견에서 마나가 제약이 된 달이 0. 마법 공격 자체도 무료다. 회복량·소모량·회복률을 같이 봐야 한다 (`docs/08` #48) |
| 난이도 6 이상 전투 | 견습 파티가 짐 | 월당 처치가 0.5대로 떨어진다. 강도가 아니라 절대 수치 문제다 — 999 스케일 전환과 함께 (`docs/08` #43) |

## 설명되지 않은 관측

측정은 됐지만 원인을 모르는 것이다. 모르는 채로 두는 것이 틀린 설명을 붙이는 것보다
낫다 — 붙인 설명은 다음 판단의 근거가 되어 버린다. 측정값은
[08-balance-log.md](08-balance-log.md)에 있다.

- 전투 오라클이 균형 방침에 41%로 진다 (#34). 숨은 성장 곡선을 다 아는 쪽이 지는 이유 미상
- 능력치 총합은 전투력의 지표가 아니다 — 총합 1위가 1:1에서 82% 패배
