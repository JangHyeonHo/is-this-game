# ADR 0002. 출시물에 생성형 AI 콘텐츠를 넣지 않는다

- **상태:** 채택
- **일자:** 2026-07
- **관련:** [10-research-tech.md](../10-research-tech.md), [11-research-art.md](../11-research-art.md)

## 맥락

아트 역량이 없고 예산이 30~50만원인 상황에서 생성형 AI로 아트를 대체하는 것은
표면적으로 매력적입니다. 게임 내 LLM NPC도 기술적 도전 목표와 맞아 보입니다.
실제 데이터를 조사했습니다.

### Steam 정책 (2026년 1월 개정)

Valve는 AI 공개 폼의 기준을 **"게임과 함께 배포되어 플레이어가 소비하는 콘텐츠"** 로 명확화했습니다.

| 용도 | 공개 의무 |
|---|---|
| **코드 어시스턴트, 디버깅 도구** | **면제** — Valve가 "이러한 도구를 통한 효율성 향상은 이 섹션의 초점이 아니다"라고 명시 |
| 내부 컨셉 탐색 (배포하지 않음) | 면제 |
| 게임 내 최종 에셋 (아트·사운드·대사·현지화) | **의무** |
| **마케팅 자료 및 스토어 페이지** | **의무** |
| 런타임 생성 콘텐츠 | 의무 + 가드레일 서술 필수. 미비 시 Steam에서 제거 가능 |

### 시장 페널티 (실측)

2023년 7월~2026년 7월 출시 Steam 게임 **53,597종 전수 조사** 결과:

- AI 사용 공개 게임은 **리뷰 수 약 53% 감소**, 리뷰 내용도 더 부정적
- 리소스가 있는 스튜디오는 **매출 40~60% 감소** 추정
- 출시 전 **위시리스트도 유의하게 적음** → 런칭 모멘텀 자체가 붕괴
- AI 공개 게임 비율: 2024년 10.9% → 2025년 19.9% → 2026년 30.8%
- GDC 2026 조사(2,300명+): 개발자 **52%가 genAI가 산업에 부정적**이라 응답 (2년 전 18%)

### 실제 사고 사례

- **The Alters** (11 bit, 2025): 미공개 AI 사용이 발각. "임시 플레이스홀더가 실수로 남았다"고 해명.
  패치로 교체. → **실패 원인은 "AI를 썼다"가 아니라 "지우지 않았고 공개하지 않았다"**
- **Shrine's Legacy** (2025): **실제 인간 아티스트만 썼는데** AI 의혹으로 리뷰 폭탄.
  개발 코드 스크린샷까지 공개해야 했음

### 저작권 상태

- 미국 저작권청 2025년 1월 보고서: **의미 있는 인간 창작 기여가 없는 AI 생성물은 저작권 보호 불가**
- Thaler v. Perlmutter: 2026년 상고 불허로 "인간만이 저작자" 원칙 확정
- Andersen v. Stability AI: 2026년 4월 기준 **진행 중**, 최종 판결 없음

→ AI로 만든 캐릭터·키비주얼은 **타인이 그대로 베껴도 막을 법적 수단이 약합니다.**
IP를 자산으로 축적하려는 프로젝트에서는 판매 감소보다 근본적인 문제입니다.

### 런타임 LLM의 경제성

- 인디 개발자 실측: 플레이 중 **하루 $9/플레이어**, "3일에 한 번 5시간" 기준 **첫 달 플레이어당 $50**
- AI Dungeon: 대역폭 비용 **$20,000 초과**로 일시 서비스 중단 → 구독제 전환
- **패키지 판매는 매출이 1회, LLM은 비용이 플레이할수록 증가.** 수학적으로 화해 불가능
- 온디바이스(Phi-4-mini, Gemma 4 E4B 등 ~3GB VRAM)는 비용을 0으로 만들지만
  **최소 사양이 크게 오르고 Steam 태그는 여전히 붙습니다**

## 결정

1. **Claude Code 등 AI 코딩 에이전트는 적극 사용한다.** Steam 공개 의무 대상이 아니다.
2. **출시물의 어떤 콘텐츠에도 생성형 AI를 쓰지 않는다.**
   게임 내 아트·사운드·대사·현지화, 그리고 **스토어 캡슐·스크린샷·트레일러 전부 포함.**
3. **런타임 LLM을 넣지 않는다.** 클라우드 API도, 온디바이스 번들도.
4. **게임 내 "AI다움"은 GOAP + Utility AI + Behavior Tree로 구현한다.**

## 근거

4번이 특히 중요합니다. 전통적 게임 AI는 이 프로젝트의 모든 지표에서 우월합니다.

| 항목 | 런타임 LLM | GOAP / Utility AI |
|---|---|---|
| 런타임 비용 | 플레이어당 지속 발생 | **0** |
| Steam AI 태그 | 붙음 (+ 가드레일 서술 의무) | **없음** |
| 리뷰 페널티 | 약 -53% | **없음** |
| 디버깅 | 확률적, 재현 어려움 | **결정론적** |
| 밸런싱 | 사실상 불가능 | 배치 시뮬레이션 가능 |
| AI 에이전트가 짜기 좋은가 | — | **최적. 순수 로직 + 테스트 가능** |
| 최소 사양 영향 | 큼 | 없음 |

그리고 심즈가 20년간 utility AI로 만들어온 "살아있음"이 곧 이 프로젝트가
원하는 "농도 있는 NPC"입니다. LLM이 필요한 게 아닙니다.

또한 리서치에서 확인된 LLM 게임의 실제 평가는 냉정합니다.
Where Winds Meet은 성공했지만 호평의 주 요인은 비주얼과 전투였고,
Whispers from the Star는 "AI 캐릭터가 성장하지 않는다"는 서사적 공허함이 핵심 실패 요인이었습니다.
성공 사례는 예외 없이 자금력 있는 스튜디오이거나 LLM이 유일한 코어인 실험작입니다.

## 프로토타입 플레이스홀더 규칙

컨셉 탐색과 프로토타입용 AI 이미지는 Steam 공개 의무가 없어 사용 가능하지만,
The Alters의 사고를 막기 위해 **기계적 제거 절차**를 강제합니다.

1. 해당 파일은 **반드시 `_PLACEHOLDER_AI/` 디렉터리에만** 둔다
2. 이 디렉터리는 `.gitignore`에 등록되어 **저장소에 커밋되지 않는다**
3. 빌드 스크립트가 이 경로 참조를 발견하면 **빌드를 실패시킨다**
4. 스토어 제출 전 체크리스트에 "플레이스홀더 잔존 검사"를 포함한다

## 결과

- 아트 예산 압박이 그대로 남는다 → [ADR 0003](0003-portrait-layering.md)의 레이어 조합 초상화와
  절차적 생성으로 해결한다
- 기술적 도전 목표는 LLM이 아니라 GOAP/Utility AI로 충족한다.
  **오히려 플레이어가 직접 만지는 시스템이 되어 게임 디자인의 중심이 된다**
- Steam AI 공개 폼에 "해당 없음"으로 제출할 수 있다
