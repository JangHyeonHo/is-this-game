# ADR 0003. 캐릭터를 레이어 조합형 초상화로 표현한다

- **상태:** 채택
- **일자:** 2026-07
- **관련:** [11-research-art.md](../11-research-art.md), [01-game-design.md](../01-game-design.md)

## 맥락

이 게임은 육성 시뮬레이션이고, 그 장르의 매력은 캐릭터에 대한 애착에서 나옵니다.
그런데 개발자는 **아트 역량이 없고 예산이 30~50만원**입니다.

- 완전 커스텀 애니메이션 캐릭터 외주는 시급 환산 **$240~800/종**.
  캐릭터 20명이면 예산의 10~20배
- 생성형 AI 아트는 [ADR 0002](0002-no-genai-in-shipped-content.md)에서 배제됨
- 3D 캐릭터는 에셋으로 조달 가능하지만 앱모드·리깅·애니메이션 부담이 큼
- 초상화를 아예 없애면 육성 시뮬 특유의 정서적 애착을 잃음

## 결정

**Battle Brothers 방식의 레이어 조합형 2D 초상화를 채택한다.**

```
[배경] → [체형] → [피부/종족] → [얼굴] → [머리] → [수염] → [흉터] → [장비] → [상태 오버레이]
```

파츠 세트 **한 벌**(예산 10~15만원)로 수천 명의 고유한 모험가를 생성합니다.

## 근거

1. **비용이 캐릭터 수와 무관해진다.** 파츠 종류 수에만 비례한다.
   각 슬롯에 8종씩만 있어도 조합 수는 수십만이다.
2. **아트가 곧 시뮬레이션 상태의 표현이 된다.** 부상 → 영구 흉터 레이어,
   노화 → 머리색 변화, 장비 교체 → 초상화 반영.
   **추가 아트 비용 없이 캐릭터가 "변화"한다.**
3. **애착은 그림이 아니라 기억에서 나온다.** RimWorld(졸라맨), Dwarf Fortress(ASCII),
   Battle Brothers(레이어 초상화)가 모두 증명했다.
   초상화는 애착의 **닻**일 뿐이고, 실체는 이력(Chronicle)이 만든다.
4. **절차적 생성이라는 기술적 도전 목표와 정확히 맞물린다.**
   아트 비용을 코드로 대체하는 일이 곧 하고 싶었던 기술 작업이 된다.
5. **파츠는 저비용으로 조달 가능하다.** 얼굴 파츠 세트는 완성 캐릭터 일러스트보다
   훨씬 싸고, 정면 고정이라 원근·포즈 문제가 없다.

## 결과

**긍정**
- 캐릭터 수를 늘려도 아트 비용이 늘지 않는다
- 캐릭터의 변화를 시각적으로 보여줄 수 있다
- 파츠를 나중에 추가하면 기존 캐릭터에도 소급 적용된다

**부정 / 비용**
- 파츠 간 **정합성**(눈 위치, 조명 방향, 선 굵기, 팔레트)을 맞추는 게 어렵다.
  → **파츠는 반드시 단일 공급원에서 조달한다.** 여러 출처 혼합은 에셋 플립 낙인의 1차 트리거다
- 조합 결과가 "기계적"으로 보일 수 있다 → 팔레트 변주와 조합 규칙(어울리지 않는 조합 배제)이 필요
- 표정 연기가 제한적이다 → 이 게임은 대사 중심이 아니므로 감수 가능
- **AI 생성으로 오인받을 위험**(Shrine's Legacy 사례). 실제 인간 아티스트만 썼는데도
  리뷰 폭탄을 맞은 전례가 있다
  → **완화책: devlog와 타임랩스로 제작 과정을 선제적으로 공개한다. 파츠 출처를 명시한다**

## 구현 노트

- 초상화 조합 로직은 `Guildwright.Core`에 둔다 (어떤 파츠 ID를 쓸지 결정하는 순수 함수).
  **실제 이미지 합성만 엔진 레이어가 담당한다.**
- 조합 결과는 모험가의 시드로부터 **결정론적으로** 재현되어야 한다.
  같은 모험가는 언제 어디서 그려도 같은 얼굴이어야 한다.
- 상태 레이어(부상·사기 등)는 조합 시드와 분리해 런타임에 덧붙인다.
