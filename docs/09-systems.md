# 시스템 현황 — 판단과 맥락

> **무엇이 존재하는가는 여기가 아니라 [09-systems.generated.md](09-systems.generated.md)에 있습니다.**
> 그쪽은 어셈블리에서 생성되고, 낡으면 `SystemInventoryTests`가 깨집니다.
>
> 이 문서에는 **코드에서 뽑을 수 없는 것만** 적습니다 — 왜 없는지, 무엇이 막고 있는지, 무엇을 미뤘는지.
> 세션 시작 훅이 두 문서를 함께 컨텍스트에 넣습니다.

## 이 장치가 왜 있는가

이미 구현된 전열/후열(`Row`), 전술 규칙(`TacticRule`), 전투 개입(`IBattleCommander`)을
"없다"고 답한 사고가 있었습니다. `PositionCombatTests.cs`라는 테스트 파일까지 있는 상태였습니다.

CLAUDE.md에는 그때도 "먼저 읽으세요"가 적혀 있었습니다. **읽는 것이 선택이면 빠집니다.**
그래서 선택을 없앴습니다 — 훅이 직접 넣고, 목록은 코드에서 생성되고, 낡으면 테스트가 깹니다.

같은 이유로 **이 문서에 타입 목록을 다시 적지 않습니다.** 두 벌이 되면 반드시 어긋나고,
어긋난 인벤토리는 아무것도 없는 것보다 나쁩니다.

## 아직 없는 것

생성 목록에 없으면 없는 것이므로, 여기 적는 건 **왜 없는지**가 필요한 항목뿐입니다.

| 없는 것 | 왜 / 비고 |
|---|---|
| 파티 시스템 | 파티 등급·동행 연차·가입 자격. 설계는 끝났고 구현만 남음 (`docs/08` 참조). `CombatantFactory.FormParty`는 전투용 조립일 뿐 |
| 성격 오라 / 시너지 | `Temperament` 3종은 *성장* 성향이고 파티 오라와 별개. 기질 6~8종 + 성향 조합식으로 2층 설계 확정 |
| 지시 불통 상태이상 | 공황·기절 추가 예정. `StatusEffect.cs`에 "적게 유지" 원칙이 있어 혼란·광폭은 보류 |
| 전투 이탈(후퇴) | `MoveBack`은 후열 이동일 뿐. "파티 전멸해도 주인공이 있어 안 죽는다"의 구현 수단 |
| 개별 장비 아이템 | 스타일+무기종 조합으로 충분한지 확인 전. 스코프 방어 목적으로 미룸 |
| 경제 구조 | 자금·유지비·보수 분배. 국가 지원 5년 뒤에야 필요해짐 |
| 직렬화/세이브 | 데이터 스키마가 아직 흔들려서 미룸. 굳기 전에 만들면 두 번 만듦 |
| 액티브/패시브 스킬 | 숙련도로 배우는 스킬. 주인님이 "존재 확인 정도로 하고 넘어가도 된다"고 함 |
| 연 단위 달력 UI | 훈련/의뢰/휴식 월별 편성. 연 구조 설계 확정 후 착수 |
| 게임 엔진 | 의도된 부재 — [ADR 0001](adr/0001-engine-agnostic-core.md) |

## 제약이 기능을 막고 있는 곳

**기능이 있는데 못 쓰는 자리.** "없다"고 결론내기 전에 여기를 먼저 봅니다 —
이번 사고의 실제 원인도 기능 부재가 아니라 이쪽이었습니다.

| 자리 | 현재 | 문제 |
|---|---|---|
| `CommandRules.BasePoints = 3` | 전투당 개입 3점, 위치 변경 2점 | 전투가 3~4라운드라 사실상 1~2번. **"개입으로 할 수 있는 게 없다"의 진짜 원인.** 주인님 결정: 횟수 제한 폐지 |
| 1인 파티 전투 | 튜토리얼이 솔로 | 전열/후열이 죽은 기능이 됨. 최소 2인이 포지션의 전제 |
| `DamageModel.MaxEvasionChance` | 회피 상한 28% | 격차 900 → 99% 설계와 안 맞음. 능력치 999 스케일 전환과 함께 교체 |
| 능력치 스케일 | 하드캡 999 결정, 공식은 구 스케일 | [08-design-revision.md](08-design-revision.md) §12 |
| `FieldYearSession` | 12개월 = 의뢰 1건 | 확정된 연 구조(월별 3지선다)와 안 맞음. 재설계 대상 |

## 설명되지 않은 관측

밸런스 로그([06-balance-log.md](06-balance-log.md))에 있지만 원인을 아직 모르는 것.
**모르는 채로 두는 게 틀린 설명을 붙이는 것보다 낫습니다.**

- 전투 오라클이 균형 방침에 41%로 집니다 (#34). 숨은 성장 곡선을 다 아는 쪽이 지는 이유 미상.
- 능력치 총합은 전투력의 지표가 아닙니다 — 총합 1위가 1:1에서 82% 패배.

## 유지 방법

| 무엇이 바뀌면 | 무엇을 한다 |
|---|---|
| 공개 타입 추가·삭제·이름 변경 | `UPDATE_INVENTORY=1 dotnet test --filter SystemInventory` → 같은 커밋에 포함 |
| 기능이 생겨서 "없는 것"에서 빠짐 | 이 문서의 표에서 줄 삭제 |
| 제약을 풀었음 | "제약이 막고 있는 곳"에서 줄 삭제 |
| 원인을 알아냄 | "설명되지 않은 관측"에서 옮기고 `06-balance-log.md`에 기록 |

첫 줄은 잊어도 테스트가 잡아줍니다. 나머지는 잊으면 그냥 낡습니다 —
그래서 **판단이 필요한 것만 손으로 두고, 나머지는 전부 생성으로 옮겼습니다.**
