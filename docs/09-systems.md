# 시스템 현황 — 판단과 맥락

> **무엇이 존재하는가는 여기가 아니라 [09-systems.generated.md](09-systems.generated.md)에 있습니다.**
> 그쪽은 어셈블리에서 생성되고, 낡으면 `SystemInventoryTests`가 깨집니다.
>
> 이 문서에는 **코드에서 뽑을 수 없는 것만** 적습니다 — 왜 없는지, 무엇이 막고 있는지, 무엇을 미뤘는지.
> 세션 시작 훅이 두 문서를 함께 컨텍스트에 넣습니다.

## 이 장치가 왜 있는가

이미 구현된 전열/후열(`Row`), 전술 규칙(`TacticRule`), 전투 개입(`IBattleCommander`)을
"없다"고 답한 사고가 있었습니다. `PositionCombatTests.cs`라는 테스트 파일까지 있는 상태였습니다.

CLAUDE.md에는 그때도 "먼저 읽으세요"가 적혀 있었습니다. **읽는 것이 선택이면 빠집니다.**
그래서 선택을 없앴습니다 — 훅이 직접 넣고, 목록은 코드에서 생성되고, 낡으면 테스트가 깹니다.

같은 이유로 **이 문서에 타입 목록을 다시 적지 않습니다.** 두 벌이 되면 반드시 어긋나고,
어긋난 인벤토리는 아무것도 없는 것보다 나쁩니다.

## ⚠ 표기 규칙 — 누가 정했는가

**이 구분 없이 적었다가 사고가 났습니다.** 에이전트의 제안을 "확정"으로 적어두면,
다음 세션이 그걸 주인님의 결정으로 읽고 확인 없이 그 위에 쌓습니다.
낡은 정보를 막으려고 만든 이 문서가 **틀린 정보를 증폭하는 통로**가 됩니다.

| 표기 | 뜻 | 다룰 때 |
|---|---|---|
| **[확정]** | 수치·규칙까지 정해짐 | 그대로 구현. 바꾸려면 물어볼 것 |
| **[방향]** | 방향은 합의됐으나 세부 미정 | **구현 착수 금지.** [확정]으로 올리지 말 것 |
| **[검토중]** | 주인님이 아직 판단 중. 방향도 미정 | 구현 착수 금지 |
| **[제안]** | 에이전트가 낸 안. 승인된 적 없음 | **주인님 결정으로 인용하지 말 것** |

눈금을 건너뛰는 것도 사고입니다. 방향만 합의된 것을 [확정]으로 올리면
"상세는 안 정했는데 확정이라 적혀 있다"가 되고, 그 위에 구현이 얹힙니다.

## 아직 없는 것

생성 목록에 없으면 없는 것이므로, 여기 적는 건 **왜 없는지**가 필요한 항목뿐입니다.

| 없는 것 | 왜 / 비고 |
|---|---|
| 파티 시스템 — 남은 것 | 구조는 **구현됨**(`Parties` — `PartyLedger` · `Party` · `PartyFormation` · `Rank`). 아직 없는 것은 **연결**입니다: 달마다 `RecordMonth`를 불러줄 달력(§15), 평가를 넣어줄 의뢰 결과 배분, 정규 파티가 **파티 전용 의뢰**를 받는 경로. **[검토중]** 평가 산정 수치(`PartyRules.EvaluationToRankUp`는 임시값), 솔로잉 해금 등급(C or D), 승급 의뢰 세부 |
| 짐 분실 규칙 | **[확정]** `docs/08` §16.8b — 짐은 **파티 전멸 시에만** 잃음. 짐이라는 자원 자체가 아직 없음(`Supplies`는 회복약만). **표적 최후순위와 후열 배치는 구현됨** |
| 성격 오라 / 시너지 | **[확정]** 1:1 조합이 아니라 파티 전체 패시브(오라). **스킬 체계의 태생 패시브로 흡수** → `docs/08` §10. 슬롯 없이 전부 적용. **[검토중]** 종류 수(36종~소수), 오라의 대상과 세기, `Temperament` 3종 흡수 여부 |
| 전투 이탈(후퇴) | **[확정]** 모험가는 생존 최우선, 견적이 안 나오면 스스로 후퇴 (`docs/08` §17.5). **`DeploymentFailure.Retreated`는 라운드 한도 초과의 라벨일 뿐** — AI 판단이 아닙니다. 후퇴 성공률이 §17.11 [검토중]이라 같이 정해야 함 (`docs/06` #52) |
| **파견 피로** | **[확정]** §17.7은 "훈련 쪽 피로가 그대로 이어지므로 따로 만들 것이 없다"고 하지만, `Fatigue`는 `TrainingYearSession` 안에만 있고 `Adventurer`에 필드가 없습니다 — **이어붙일 대상이 없어 새로 만들어야** 합니다. 지금은 **중도 이탈 직후 무제한 재파견**이 됩니다. §17.7이 유일한 브레이크로 지목한 것 (`docs/06` #52) |
| **호위 대상** | **[확정]** §17.5 "호위 대상 보호가 최우선". `Contract.Objective`는 표시용 문자열이고 `ObjectiveLost`는 "전투에서 이기지 못했다"의 다른 이름입니다. 지켜야 할 개체와 AI 우선순위가 필요 |
| **비전투 역량이 진척에** | **[확정]** §17.3 "비전투 역량이 주역이 되는 자리". `DeploymentSession.WorkShare`는 파티를 아예 보지 않아 진척이 편성과 무관합니다 |
| **길드원 정원 · 매달 정책** | **[확정]** §17.10. `Calendar.IsRecruitmentMonth`는 있지만 **호출부가 없고**, 랭크별 정원 규칙은 코드에 없습니다. 콘솔이 연 1회 루프이고 게시판을 `month: 1` 고정으로 부르므로 **계절 가중치 전체가 실행 경로에서 죽어 있습니다** |
| 개별 장비 아이템 | 스타일+무기종 조합으로 충분한지 확인 전. 스코프 방어 목적으로 미룸. **가방도 여기에 들어갈 예정** (무기 표의 한 줄, 위력 0 · 적재량) |
| 경제 구조 | **[확정]** 연봉 폐지 → 유지비 + 보수 분배. 자금 타입 자체가 없음. **[검토중]** 국가 지원 기간 — 5년은 1년 단위 육성 전제로 잡은 값이라 재검토 (튜토리얼 1년은 유지) |
| 직렬화/세이브 | 데이터 스키마가 아직 흔들려서 미룸. 굳기 전에 만들면 두 번 만듦 |
| 스킬 체계 | **[확정]** 논의 완료 — `docs/08` §10. 전부 새로 짬 · 태생/직업 × 패시브/액티브 · **패시브는 슬롯 없이 전부 적용, 액티브만 골라서 장착** · 슬롯 수는 직업 데이터에 · 액티브는 특정 무기 요구 · **마나 + 쿨다운 둘 다** (마나는 하나로 통일하되 소모량이 스킬마다 다름) · 직업 패시브는 전직해도 남음. **[검토중]** 직업당 스킬 개수, 슬롯 수, 쿨다운 단위 |
| **직업 체계** | **[확정]** 논의 완료 — `docs/08` §16. **무기와 별개 축** · 숙련도 조합으로 히든 직업 해금(활60+지팡이60 = 마궁사) · 조합은 평균이 아니라 합집합 · 전직 자유(대가는 숙련 0부터) · 희망 직업을 캐릭터가 가지고 옴 · **데이터 주도 필수**(수십 종 예정). **[검토중]** 조합 직업 균형, 숙련 상한 100, 칭호 |
| **이해도** | **[확정]** `ScoutingReport.Confidence`의 진화형 — `docs/08` §16.7. 한 달 육성 +1%, 멘토가 가속, **멘토와 숨은 특성이 같으면 더 빠름**. 특성·패시브가 확률로 하나씩 공개, 50%에서 개수 공개. **[검토중]** 공개 확률 곡선 |
| 의뢰 구조 — 남은 것 | 형태 4종·기간 고정·이분법·랜덤 발생·랭크 조절·지속 의뢰·중도 이탈은 **구현됨**(`Contract` · `ContractBoard` · `DeploymentSession`). 없는 것은 **달력 잠금**(§15) — 그게 없으면 과잉 전력을 막는 기회비용이 성립하지 않습니다. **[검토중]** 겨울 성격, 후퇴 성공률, 실패 페널티 세부, 보수 액수 |
| **연 달력 (달 단위 잠금)** | **[확정]** 매달 정책 · 잠금은 예약(중도 이탈 가능) · **파티 인정은 함께 나간 6개월**. `Adventurer.MonthsElapsed`와 `DeploymentSession`이 달 단위로 돌아가지만 **12칸을 잠그는 달력 자체가 없습니다** — 지금 콘솔은 아직 연 단위 루프입니다. 이것이 남은 가장 큰 구멍입니다. **[검토중]** 동행 잠금 세부, 자동방침이 잠긴 칸을 계산하는 방식. `docs/08` §15 |
| 게임 엔진 | 의도된 부재 — [ADR 0001](adr/0001-engine-agnostic-core.md) |

## 제약이 기능을 막고 있는 곳

**기능이 있는데 못 쓰는 자리.** "없다"고 결론내기 전에 여기를 먼저 봅니다 —
이번 사고의 실제 원인도 기능 부재가 아니라 이쪽이었습니다.

| 자리 | 현재 | 문제 |
|---|---|---|
| 1인 파티 전투 | 튜토리얼이 솔로 | 전열/후열이 죽은 기능이 됨. 최소 2인이 포지션의 전제. **콘솔에서 견습 솔로 파견은 거의 확정 패배**(`docs/06` #40) — 다만 솔로잉은 이제 개인 등급 D부터 열리므로, 자격 있는 캐릭터로 다시 재야 판정이 됩니다 |
| `DamageModel.MaxEvasionChance` | 회피 상한 28% | 격차 900 → 99% 설계와 안 맞음. 능력치 999 스케일 전환과 함께 교체 |
| 능력치 스케일 | 하드캡 999 결정, 공식은 구 스케일 | [08-design-revision.md](08-design-revision.md) §12 |
| `StyleCapability` | 회복·도발·광역·마법·후열타격·치명타를 무기가 결정 | **[확정]** 전부 스킬로 이동. 무기에는 위력·속도·사거리만 남음 (`docs/08` §16.2) |
| `WeaponStyle` 열거형 | 스타일 7종 + 능력표가 코드에 하드코딩 | **[확정]** 데이터 주도로 전환. 무기를 **주/보조 × 좌/우 4칸**에 들게 하면 손 배치가 곧 스타일이라 열거형 자체가 사라짐 (`docs/08` §16.2b) |

| `SupportSkill` 5종 | 함정감지·척후·운반·채집·감정이 별개 축 | **[확정] 폐기.** 에이전트가 상의 없이 만든 개념. 스킬 체계가 담당함. `SupportSkillSet`·`ContractSupport`·`Appraiser`의 감정역량 인자도 함께 (`docs/08` §16.8c) |
| ~~`TacticalBrain`의 `AttackWeakest`~~ | ~~마물이 짐꾼만 골라 침~~ | **해결됨** — `BattleState.ReachableTargets`가 가방을 든 사람을 후순위로 뺍니다 |
| 마나 | 자연회복 15%가 주문 한 발보다 큼 | 8달 파견에서 **마나가 제약이 된 달이 0**. 마법 공격 자체도 무료. 회복량·소모량·회복률을 같이 봐야 함 (`docs/06` #48) |

| 콘솔의 연 단위 루프 | `month: 1` 고정 | **계절 가중치 전체가 실행 경로에서 죽어 있음.** 1달 의뢰를 받아도 게임 시간은 1년이 감 — `share` 곱이 코어에서 막은 것을 콘솔이 되돌림 (`docs/06` #49) |

## 유지 방법

| 무엇이 바뀌면 | 무엇을 한다 |
|---|---|
| 공개 타입 추가·삭제·이름 변경 | `UPDATE_INVENTORY=1 dotnet test --filter SystemInventory` → 같은 커밋에 포함 |
| 기능이 생겨서 "없는 것"에서 빠짐 | 이 문서의 표에서 줄 삭제 |
| 제약을 풀었음 | "제약이 막고 있는 곳"에서 줄 삭제 |
| 원인을 알아냄 | "설명되지 않은 관측"에서 옮기고 `06-balance-log.md`에 기록 |

첫 줄은 잊어도 테스트가 잡아줍니다. 나머지는 잊으면 그냥 낡습니다 —
그래서 **판단이 필요한 것만 손으로 두고, 나머지는 전부 생성으로 옮겼습니다.**
