# 시스템 현황 — 판단과 맥락

> **무엇이 존재하는가는 여기가 아니라 [09-systems.generated.md](09-systems.generated.md)에 있습니다.**
> 그쪽은 어셈블리에서 생성되고, 낡으면 `SystemInventoryTests`가 깨집니다.
>
> 이 문서에는 **코드에서 뽑을 수 없는 것만** 적습니다 — 왜 없는지, 무엇이 막고 있는지, 무엇을 미뤘는지.
> 세션 시작 훅이 두 문서를 함께 컨텍스트에 넣습니다.

## 이 장치가 왜 있는가

이미 구현된 전열/후열(`Row`), 전술 규칙(`TacticRule`), 전투 개입(`IBattleCommander`)을
"없다"고 답한 사고가 있었습니다. `PositionCombatTests.cs`라는 테스트 파일까지 있는 상태였습니다.

CLAUDE.md에는 그때도 "먼저 읽으세요"가 적혀 있었습니다. **읽는 것이 선택이면 빠집니다.**
그래서 선택을 없앴습니다 — 훅이 직접 넣고, 목록은 코드에서 생성되고, 낡으면 테스트가 깹니다.

같은 이유로 **이 문서에 타입 목록을 다시 적지 않습니다.** 두 벌이 되면 반드시 어긋나고,
어긋난 인벤토리는 아무것도 없는 것보다 나쁩니다.

## ⚠ 표기 규칙 — 누가 정했는가

**이 구분 없이 적었다가 사고가 났습니다.** 에이전트의 제안을 "확정"으로 적어두면,
다음 세션이 그걸 주인님의 결정으로 읽고 확인 없이 그 위에 쌓습니다.
낡은 정보를 막으려고 만든 이 문서가 **틀린 정보를 증폭하는 통로**가 됩니다.

| 표기 | 뜻 | 다룰 때 |
|---|---|---|
| **[확정]** | 수치·규칙까지 정해짐 | 그대로 구현. 바꾸려면 물어볼 것 |
| **[방향]** | 방향은 합의됐으나 세부 미정 | **구현 착수 금지.** [확정]으로 올리지 말 것 |
| **[검토중]** | 주인님이 아직 판단 중. 방향도 미정 | 구현 착수 금지 |
| **[제안]** | 에이전트가 낸 안. 승인된 적 없음 | **주인님 결정으로 인용하지 말 것** |

눈금을 건너뛰는 것도 사고입니다. 방향만 합의된 것을 [확정]으로 올리면
"상세는 안 정했는데 확정이라 적혀 있다"가 되고, 그 위에 구현이 얹힙니다.

## 아직 없는 것

생성 목록에 없으면 없는 것이므로, 여기 적는 건 **왜 없는지**가 필요한 항목뿐입니다.

> ⚠️ **[검토중]을 두 뜻으로 섞어 쓰지 마세요.** "주인님이 정할 것"과 "에이전트가 만들거나
> 시뮬레이션으로 잴 것"은 다릅니다. 후자를 [검토중]으로 적으면 **주인님께 없는 숙제가
> 생깁니다.** 실제로 그 사고가 났습니다 — 전수 분류는 `docs/06` #55에 있습니다.
>
> **주인님 결정이 필요한 것은 지금 둘뿐입니다**: 국가 지원 기간 · 솔로잉 해금 등급(C냐 D냐).
> 나머지는 전부 **에이전트가 만들 것**이거나 **돌려서 결과를 가져올 것**입니다.

| **설계 대조 리뷰** | ✅ 2026-07-30, 에이전트 3인. 찾은 것 전부 `docs/06` #42~#52. `DesignConformanceTests` 26개가 회귀를 막습니다 — **전부 테스트를 통과하면서 들어와 있던 것들**입니다 |
| **달 단위 달력** | ✅ 콘솔이 **매달** 굴러갑니다. 1월 모집(랭크별 정원) · 계절별 게시판 · 의뢰를 받으면 **그 기간만큼 칸이 잠김** · 중도 이탈하면 풀림 · 훈련은 몇 달만 해도 결산됨(`TrainingYearSession.Settle`). §17.4가 유일한 브레이크로 지목한 **기회비용이 여기서 처음 성립합니다** (`docs/06` #56) |
| **파티가 인게임에** | ✅ 파견 조합이 장부에 쌓이고 화면에 진행 바로 보입니다. 정규 등록 제안 · 평가 누적 · 1명 남으면 해체 · 파티 전용/승급 의뢰. **실제 플레이에서 정규 파티가 등록되는 것을 확인** |
| **전직이 인게임에** | ✅ 매달 선택지. 수주 난이도 내림차순 정렬이라 사다리의 다음 단이 맨 위입니다. **이게 없으면 영구히 견습이라 승급이 E급에서 막혔습니다** (`docs/06` #57) |

## 설명되지 않은 관측

밸런스 로그([06-balance-log.md](06-balance-log.md))에 있지만 원인을 아직 모르는 것.
**모르는 채로 두는 게 틀린 설명을 붙이는 것보다 낫습니다.**

- 전투 오라클이 균형 방침에 41%로 집니다 (#34). 숨은 성장 곡선을 다 아는 쪽이 지는 이유 미상.
- 능력치 총합은 전투력의 지표가 아닙니다 — 총합 1위가 1:1에서 82% 패배.

## 유지 방법

| 무엇이 바뀌면 | 무엇을 한다 |
|---|---|
| 공개 타입 추가·삭제·이름 변경 | `UPDATE_INVENTORY=1 dotnet test --filter SystemInventory` → 같은 커밋에 포함 |
| 기능이 생겨서 "없는 것"에서 빠짐 | 이 문서의 표에서 줄 삭제 |
| 제약을 풀었음 | "제약이 막고 있는 곳"에서 줄 삭제 |
| 원인을 알아냄 | "설명되지 않은 관측"에서 옮기고 `06-balance-log.md`에 기록 |

첫 줄은 잊어도 테스트가 잡아줍니다. 나머지는 잊으면 그냥 낡습니다 —
그래서 **판단이 필요한 것만 손으로 두고, 나머지는 전부 생성으로 옮겼습니다.**
