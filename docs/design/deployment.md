# 설계 — 의뢰와 파견

의뢰가 어떻게 만들어지고, 파견이 달 단위로 어떻게 진행되고, 끝나면 어떻게 결산되는지를
적는다. 게임 규칙 관점은 [../01-game-design.md](../01-game-design.md) §5 · §6에 있다.

## 의뢰 — 정의와 생성

의뢰(`Contract`)는 형태(`ContractForm` — 토벌·지킴·수집·발견) · 출처 · 난이도 · 기간 ·
강도 · 승급 여부를 가진 레코드다. **형태가 완료 판정을 정하고, 이름은 데이터다.**
플레이어가 보는 의뢰 이름은 `ContractFlavor`의 이름 풀에서 나온다.

게시판(`ContractBoard`)이 달마다 의뢰를 생성한다. 길드 랭크가 개수 기대값과 난이도
상한을 함께 조절하고, 계절이 형태별 가중치를 바꾼다. 난이도 하한은 상수다 — 하한을
랭크에 따라 올리면 신입이 받을 의뢰가 사라진다.

강도(전투량)는 **기간에서만** 계산하고 난이도를 곱하지 않는다. 난이도는 이미 적의
세기에 반영되어 있으므로, 강도에도 곱하면 난이도가 두 번 적용된다.

승급 의뢰는 `PromotionTo`가 붙은 지속 의뢰다. `PromotionFor`가 대상(개인/파티)의
현재 등급에 맞는 승급 의뢰를 만든다.

## 파견 — 달 단위 세션

`DeploymentSession`이 파견 하나를 담는다. 훈련 세션과 같은 모양이다 — 달마다
`AdvanceMonth`, 도중 이탈은 `Abandon`, 끝나면 `Complete`가 `DeploymentResult`를 낸다.

한 달 안에서 일어나는 일: 조우 판정(형태별 확률 — 토벌은 만나는 것이 전제라 항상
조우) → 전투가 나면 해석 → 일할지 쉴지 판단 → 진척 누적. HP·마나·회복약은 세션
상태로 달을 넘어 이어지고, 자연 회복과 휴식 회복이 붙는다. 회복 판단(`HealthRatio`)은
**서 있는 멤버만** 본다 — 쓰러진 멤버를 분모에 넣으면 영원히 쉬기만 한다.

보급(`Supplies`)은 짐 한도 안에서만 된다. 한도 = 인원별 기본 휴대 + 장착의 적재량
합(가방이 여기서 효과를 낸다). 실패는 `DeploymentFailure`로 구분된다 — 전멸 · 후퇴 ·
포기 · 대상 상실 · 미발견 · 미달.

진척 판정은 형태를 따른다. 수집·발견은 일한 달수가 채워져야 하고, 지킴은 진척 판정이
없으며(버티면 성공), 토벌은 처치가 목표 수량을 채워야 한다.

## 결산

`CareerSimulator`가 파견 결과를 모험가의 성장으로 바꾼다. 성장 · 보수 · 사고 위험 ·
판단력 획득이 전부 **실제로 보낸 달수에 비례**한다 — 비례하지 않으면 짧은 의뢰 반복이
최적해가 된다. 승급 의뢰를 성공하면 여기서 등급이 오른다.

전투에서 겪은 것(`CombatExperience`)은 성장 방향에 반영된다. 보수는 출처를 따른다 —
길드 자체 의뢰는 돈 대신 명성이다.
