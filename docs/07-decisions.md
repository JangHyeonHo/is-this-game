# 07. 결정 기록

설계 논의에서 무엇이 어떻게 정해졌는지를 시간 순서로 쌓은 기록이다. 어떤 규칙을 왜
그렇게 정했는지, 그리고 그것이 합의된 결정인지 에이전트의 제안인지 가려야 할 때 본다.
지금 규칙이 무엇인지는 [01-game-design.md](01-game-design.md)가 답한다.

항목마다 표기가 붙는다. 이 표기가 결정과 제안을 가르는 유일한 장치다.

| 표기 | 뜻 | 구현 |
|---|---|---|
| **[확정]** | 수치·규칙까지 정해짐 | 착수 가능 |
| **[방향]** | 방향은 합의, 세부 미정 | 착수 불가 |
| **[검토중]** | 판단 대기 | 착수 불가 |
| **[제안]** | 에이전트 안. 승인된 적 없음 | 결정으로 인용하지 않는다 |
| **[대체됨]** | 더 뒤의 항목이 대체함 | 그 항목을 본다 |

이 문서를 다루는 규칙(추가 전용 · 표기 사용법)은 [README.md](README.md) §1 · §3에 있다.

없습니다.** 의뢰가 1달짜리 위주면 파티가 자주 바뀌므로 동행 조건이 빡세면 안 되고,
3달짜리 위주면 반대입니다. 성격 오라의 세기도 "한 달 안에 체감되는가"에 달려 있습니다.

## 1. 튜토리얼 · 시작 구조

> **[일부 대체됨 → §19]** "진실 공개"와 "반드시 틀리는 성장 곡선의 고정 캐릭터"는
> 평가서 제거(§19)로 대체되었다. 나머지(고정 캐릭터 · 나무검 · 1년 육성 · 주인공 짐꾼
> 동행 첫 의뢰 · 건너뛰기 · 모집 1명씩)는 유효하다.

**흐름**

```
길드 창설
  → 첫 캐릭터 모집 (고정 캐릭터)
  → 나무검 지급 (맨손 → 임시 무기)
  → 1년 육성
  → 진실 공개              ← 튜토리얼의 핵심
  → 첫 의뢰: 가도 정리 (난이도 1, 고블린 10마리)
     주인공이 짐꾼으로 동행 — 전투 비참여, 위기 때 포션만 지급
```

**진실 공개.** 이 게임이 가르쳐야 할 것은 메뉴 사용법이 아니라 **평가서는 틀린다**는 사실입니다.
글로 설명하면 안 읽히므로, 1년이 끝난 뒤 실제와 대조해서 보여줍니다.

```
              평가서가 말한 것          실제
  개화 시기    일찍 피는 편             대기만성형    ← 틀렸습니다
  기질        훈련장에서 배우는 타입     실전형        ← 틀렸습니다
  잠재력 힘    52                      71
```

**튜토리얼 캐릭터는 고정합니다.** 무작위면 평가서가 우연히 맞아버려 가르칠 게 사라집니다.
**반드시 틀리는** 성장 곡선을 심어둡니다.

**튜토리얼은 건너뛸 수 있어야 합니다.** "한 번 더"가 이 게임의 판단 기준인데
매번 같은 튜토리얼을 강제하면 그게 무너집니다.

**주인공은 전투에 참여하지 않습니다.** 현역급 능력치로 난이도 1 고블린을 상대하면
혼자 다 잡아버려서, 1년 훈련의 결과가 화면에 나타나지 않습니다.
위기 때 포션을 던져주는 역할만 합니다 — 짐꾼이 무엇을 하는 사람인지 한 장면에 가르칩니다.

**주인공은 튜토리얼 이후 파견을 나가지 않습니다.** 그래서 주인공의 사망 처리를 지금 정하지 않아도 됩니다.

### 시작 2년은 수입이 없습니다 — 의도된 것

```
1년차   튜토리얼 캐릭터 1명 육성 → 주인공과 첫 의뢰 (2인 충족)
2년차   주인공 빠짐. 신규 1명 모집 → 둘 다 육성 (신규는 등록 첫 해라 실전 불가)
3년차   비로소 둘이 파티로 나갈 수 있음
4~5년차 국가 지원이 남아 있는 마지막 구간
```

**모집은 1명씩입니다.** 튜토리얼에서 한 명, 직후에 한 명.

2년차 수입이 0인 것은 **국가 지원(§7)이 덮습니다.** 지원 5년 중 앞의 2년이
튜토리얼과 준비 기간이라, **실질적으로 지원을 누리는 건 3년**입니다.

## 2. 훈련 재설계 — 활동 기반

### 지금 무엇이 문제인가

`TrainingFocus`가 능력치 6개와 **1:1로 붙어 있습니다.** 고른 것 외에는 8%만 오릅니다(파급).
그래서 12개월 계획의 실체가 **같은 6지선다를 12번 반복**하는 것입니다.
3월의 선택지와 11월의 선택지가 완전히 동일합니다.

### 바꿀 것

훈련 항목을 능력치 이름이 아니라 **활동 이름**으로 바꾸고, 각각이 **가중치 벡터**를 갖습니다.

구현된 표는 [03-formulas.md](03-formulas.md) §5.1에 있습니다.
활동 6종(근력·지구력·기술·학술·명상·모의전) + 휴식이며, **피로 비용도 활동마다 다릅니다.**

> ⚠️ 가중치와 피로 비용은 전부 임시값입니다. 배치 시뮬레이션으로 잡아야 합니다.

**얻는 것**

- **선택이 실제로 갈립니다.** 지구력을 시키면 민첩과 활력이 같이 오르니 "민첩만 순수하게"가 불가능합니다
- **숙련도가 처음으로 선택 대상이 됩니다.** 지금은 훈련 선택과 무관하게 자동으로 연 9씩 오릅니다
- **그림이 그려집니다.** 아트가 없는 게임에서 "달리기를 시켰다"가 "민첩 훈련"보다 훨씬 잘 읽힙니다
- **파급(8%)을 없앨 수 있습니다.** 훈련이 이미 여러 스텟에 걸치므로 파급의 역할이 사라집니다 — 규칙이 하나 줄어듭니다

**대가**

`docs/08`의 훈련 관련 밸런스 측정치가 **전부 무효**가 됩니다. 다시 재야 합니다.

### 미해결 — 기술 훈련의 숙련도 획득량

숙련도 축이 곧 **스킬 해금 축**이 되므로(§10), 획득량을 지금 정하고 나중에 뒤집으면
해금 순서가 통째로 어긋납니다. **스킬을 설계할 때 같이 정합니다.** 그때까지 잠정값.

## 3. 훈련 부상 제거 · 실패 등급

**육성에도 부상, 실전에도 부상은 중복입니다.** 부상은 실전의 대가로 두고,
육성의 대가는 **잃어버린 한 달**로 충분합니다.

| 결과 | 성장 | 피로 |
|---|---|---|
| 대성공 | 크게 | +17 |
| 성공 | 보통 | +17 |
| 부진 | 적게 | +17 |
| **실패** | **거의 없음** | **+25** |
| 휴식 | 없음 | −38 |

실패가 휴식보다 확실히 나쁩니다 — 성장도 없는데 피로만 더 쌓입니다.
그리고 **실패가 연쇄를 부릅니다.** 피로가 더 쌓이니 다음 달 실패 확률이 올라갑니다.
부상 없이도 "무리하면 무너진다"가 성립합니다.

**사라지는 것** — 요양 개월, 훈련 부상 능력치 손실, 요양 중 선택 무시,
그리고 거기 딸린 계획 화면 분기. **규칙이 줄어드는 변경입니다.**

**추가할 것** — 실패 확률을 화면에 표시. 우마무스메가 퍼센트를 대놓고 보여주는 게 핵심인데
지금은 피로만 보여주고 확률은 숨겨져 있습니다.

### 휴식의 등급

휴식에도 대성공/성공/실패를 둡니다. 단 **피로 회복량은 고정**하고
**컨디션 회복 정도만** 등급으로 가릅니다.

이유: 피로가 난수를 타면 계획 화면의 12개월 피로 예보가 더 이상 정확하지 않게 됩니다
(#26에서 정확한 예보를 만든 게 피로에 난수가 안 끼기 때문이었습니다).
**정확한 정보가 하나쯤 남아 있는 게 좋습니다.**

## 4. 능력치 하드캡 999

**999는 하드캡이지 도달 목표가 아닙니다.** 실제 잠재력은 대부분 그보다 훨씬 낮게 굴려지고,
상급 멘토(우마무스메의 서포터 카드에 해당)가 붙기 시작하면 서서히 근접합니다.

### 대부분은 그대로 스케일됩니다

| | 현재 (활력 75, 힘 70) | 999 상한 |
|---|---|---|
| 최대 HP | 266 | 3,596 |
| 물리 위력 | 88 | 1,299 |
| 한 대 피해 | 70 | 1,049 |
| 전투 길이 | 3.8라운드 | 3.4라운드 |

위력·방어·HP가 전부 1차식이라 비율이 보존됩니다.

### 깨지는 것

**① 치명타율·회피율이 중간에 포화합니다** → §5에서 공식 교체로 해결

**② 실전 보정이 무의미해집니다.** "겪어서 얻은 것"(최대 HP +60, 위력 +20 등)이
999 스케일에서는 반올림 오차 수준입니다. **이력이 캐릭터를 다르게 만든다는 설계가 사라집니다.**
→ 보정 상한을 절대값이 아니라 스케일에 맞춰 재설계해야 합니다.

**③ 성장 곡선이 폭주할 수 있습니다.** `(잠재력 − 현재) × 비율` 구조라
잠재력이 999에 가까우면 첫 해에 300쯤 오릅니다. 하드캡으로 두면 대부분 문제없지만,
멘토로 잠재력을 끌어올릴 때 이 구간에 들어갑니다.

### 미해결 — 멘토가 잠재력을 올리는가

서포터 카드처럼 만들려면 **멘토가 잠재력 자체를 올려야** 합니다.
지금 `Mentorship`은 훈련 배율만 올려서 잠재력에 **더 빨리 도달**하게 할 뿐입니다.

이건 게임의 성격을 바꿉니다.

> 평가서가 추정하는 잠재력이 더 이상 "진짜 상한"이 아니게 됩니다.
> **"타고난 것을 알아보는 게임"에서 "타고난 것 + 투자로 만들어가는 게임"으로** 바뀝니다.

나쁜 게 아니라 다른 것입니다. 우마무스메가 정확히 후자입니다.
다만 **감정·확신도 시스템의 무게가 줄어듭니다.** 멘토를 손볼 때 결정합니다.

## 5. 명중 · 회피 · 치명타 공식 교체

### 방침 전환

지금 공식은 **극단적 빌드가 아예 불가능하게** 막혀 있습니다.
"이상한 게 안 나오게" 상한을 걸었는데 그게 "재미있는 것도 안 나오게" 만들고 있습니다.

> 너무 다 억죄면 오히려 재미요소를 급감시키는 경우가 있습니다.

**극단을 허용하되, 대가를 치르게 하는 쪽으로 바꿉니다.**

### 명중과 회피 — 두 축으로 분리

두 축을 가르는 것은 **숙련도와 판단력**입니다.
숙련도는 명중에 기여하지만 회피에는 기여하지 않습니다 — 활을 오래 쐈다고 잘 피하게 되진 않으니까요.
반대로 판단력("물러설 때를 안다")은 회피에 기여합니다.

```
명중 = (민첩 × a + 기교 × b) + 무기 숙련도
회피 = 민첩 × 1.3 + 기교 × 0.3 + 판단력
```

| 무기 | 민첩 a | 기교 b |
|---|---|---|
| 쌍수 | 1.0 | 0.3 |
| 한손+방패 | 0.7 | 0.6 |
| 양손 | 0.6 | 0.7 |
| 창 | 0.7 | 0.6 |
| 활 | 0.3 | 1.0 |
| 석궁 | 0.1 | 1.2 |
| 지팡이 | 0.3 | 1.0 |

**결과** — 도적(쌍수·민첩)은 회피도 명중도 높습니다. 판타지 관례대로입니다.
궁수(활·기교)는 **명중은 높지만 회피는 낮습니다.**
"회피 잘하는 애가 명중도 잘하는가"의 답이 **"쓰는 무기에 따라 다르다"**가 되고,
그게 곧 직업 성격이 됩니다.

**무기 속도 배율**은 명중으로 옮기지 않고 행동 순서에만 씁니다.
무기별 `a`, `b` 가중치가 이미 무기 성격을 표현하므로 중복입니다.

### 회피율 곡선

```
격차 = 방어자 회피 − 공격자 명중

격차 ≥ 0:   회피율 = 0.04 + 0.96 × 격차⁴ / (격차⁴ + 300⁴)
격차 < 0:   회피율 = 0.04 × 300⁴ / (300⁴ + |격차|⁴)
```

| 격차 | 회피율 |
|---|---|
| −900 | 0.05% |
| 0 | 4% |
| 150 | 9.7% |
| **200** | **19.8%** |
| 300 | 52% |
| 500 | 89% |
| **900** | **98.8%** |

`0.04 + 0.96 = 1.0`이라 **점근선이 정확히 100%**입니다. 자르는 게 아니라 구조적으로 못 넘습니다.

`격차⁴`는 곱셈 세 번이라 IEEE-754가 비트 단위로 보장합니다.
로지스틱(`Math.Exp`)으로도 같은 모양이 나오지만 그건 부동소수점 위험 지점(#28)이라 피합니다.

**검증한 시나리오**

| 상황 | 명중 | 회피 | 격차 | 회피율 |
|---|---|---|---|---|
| 극한 궁수 vs 극한 회피 도적 | 1,129 | 1,429 | +300 | **52%** |
| 신궁 vs 하급 도적 | 1,129 | 107 | −1,022 | 0.03% |
| 평범한 둘 (민첩·기교 300) | 440 | 530 | +90 | 4.9% |

"도적은 회피율이 높다"가 **절대 수치가 아니라 상대 개념**이라, 하급 도적이 신궁의 화살을
피하는 억울한 상황이 구조적으로 안 생깁니다. 비율/고정 확률로 회피를 주는 게임에서만 생기는 문제입니다.

### 치명타 — 100% 허용

```
치명타율 = clamp(기교 / 1200 × 스타일 배율, 0, 1.0)
```

| | 기교 999에서 | 치명타 배수 | 평균 피해 배율 |
|---|---|---|---|
| 쌍수 (1.9) | **100%** (기교 632에서 도달) | 1.4 | **1.40×** |
| 양손 (0.55) | 46% | 2.1 | **1.50×** |

**쌍수는 100%를 찍을 수 있고, 그래도 양손을 못 이깁니다.**
확률과 배율을 반대로 배치해둔 기존 설계가 여기서 값을 합니다.

치명타는 100%를 허용하고 회피는 90%대에 수렴시키는 이유 —
**치명타 100%는 "강함"이지만 회피 100%는 "게임 종료"**입니다.
후자는 전투가 라운드 상한까지 가서 무승부로 끝납니다.

### 미해결 — 계수

- 숙련도가 명중에 얼마나 기여하는가 (`c`). 숙련도는 이미 피해 배율로도 쓰이므로
  **하나가 두 번 값을 합니다.** 잘못 잡으면 "기술 훈련만 시키는 게 정답"이 됩니다
- 회피 곡선의 50% 지점 (지금 300). **실제 능력치 분포를 봐야 아는 값**입니다
- 실전 회피 보정(`DerivedBonuses`)을 새 회피 수치에 맞춰 절대값으로 재설계

### 경고 — 적 설계가 훨씬 민감해집니다

이 곡선은 명중/회피 격차를 **게임에서 가장 결정적인 수치**로 만듭니다.
격차 500이면 공격 6번 중 5번이 빗나갑니다.

적의 명중이 플레이어 회피보다 300쯤 낮으면 그 전투는 시작부터 끝난 것이고, 반대면 손도 못 씁니다.
**적 설계를 감으로 하면 안 됩니다.** `03-formulas.md` §8의 "낮은 난이도의 적 생성" 문제가 여기서 커집니다.

또 하나 — **극한 대 극한(52%)은 괜찮지만 극한 대 보통은 99%**입니다.
회피 특화가 명중에 투자 안 한 상대에게 사실상 무적이 됩니다.
999가 하드캡이라 당분간은 이론이지만, **멘토로 999에 접근하기 시작하면 실제로 터집니다.**

## 6. 파티 시스템

> 2026-07-29 대화에서 정리. 표기 없는 항목은 **[확정]** 입니다.

### 6.0 두 층 구조 — 가상 파티 / 정규 파티

**파티는 처음부터 등록하는 게 아닙니다.** 같이 나가다가 조건이 채워지면 등록할 수
있게 되고, 그때 등록합니다.

| 층 | 무엇 | 등급 | 파티 전용 의뢰 |
|---|---|---|---|
| **가상 파티** (= 임시 조합) | 의뢰에 같이 나가는 조합. 정규를 목표로 **누적이 쌓입니다** | 없음 | 못 받음 |
| **정규 파티** | 함께 나간 **6개월**을 채우고 등록한 것 | 쌓임 | 받음 |

> **층은 둘입니다.** 이 문서에는 한때 "임시 조합 / 가상 파티 / 정규 파티" 3층으로
> 적혀 있었는데(**에이전트가 늘린 층, 폐기**), 임시 조합과 가상 파티는 같은 것을
> 두 이름으로 부른 것입니다. **자격 없이 그냥 같이 나가는 층은 없습니다.**

**가입 자격이 있어야 그 멤버와 가상 파티를 구성할 수 있습니다.**
파티를 만들어야 자격이 생기는 게 아닙니다. 자격이 안 맞으면 **조합 자체가 안 됩니다** —
같이 내보내 놓고 누적만 안 쌓이는 게 아니라, 애초에 같이 못 나갑니다.
"캐리 태우기"가 성립할 자리가 없습니다.

이 구조가 만드는 것:

- **놓칠 일이 없습니다.** 누적은 자동이라 "어느새 이 셋이 조건을 채웠네"가 됩니다
- **등록이 선택이 됩니다.** 한 사람은 정규 파티 하나뿐이니, 여러 조합이 조건을 채웠을 때
  **누구와 등록할까**가 판단이 됩니다
- **강제가 아닙니다.** 등록 안 해도 게임은 굴러갑니다. 숙제가 아니라 성취입니다

### 6.1 구성 규칙

```
최소 인원      2명 (솔로잉은 C~D등급 이상만 — [검토중] 어느 쪽인지)
등록 조건      함께 나간 6개월 (달 단위 누적)
가입 자격      그 파티 등급 − 2 이상 ([방향] "−2등급까지만 허용되거나 그런식으로")
               등급이 없는 가상 파티는 제한이 걸릴 기준이 없으므로 누구나 모일 수 있음
증원           새 멤버도 그 파티와 6개월을 채워야 합류
해체           남은 멤버가 1명이면 자동 해체
유지 조건      인원만 유지되면 됨. 활동 조건 없음
소속           한 사람은 정규 파티 하나. 단 정규 파티원이 다른 조합에 나가는 것은 가능
짐꾼           최대 1명 · 짐꾼만으로 구성 불가 · 짐꾼 솔로잉 금지 (§16.8b)
```

**등급은 F ~ SS (8단계)** — 개인과 파티 모두. 지금 코드는 5단계입니다.

활동 유지 조건을 두지 않은 이유 — **파티를 만들어두고 솔로잉만 하는 플레이가 나올
이유가 없습니다.** 규칙으로 막을 필요가 없으므로 규칙을 늘리지 않습니다.

증원에 다시 6개월이 걸리므로 **죽음의 대가가 남습니다.** 빈자리를 즉시 메울 수 없고,
그동안 파티는 줄어든 인원으로 굴러갑니다. 다만 1명이 될 때까지는 해체되지 않으므로
파국은 아닙니다.

### 6.2 파티 등급은 독립적으로 쌓입니다

**개인 등급에서 파생되지 않습니다.** 파티를 짰다고 처음부터 A나 S가 되지 않고,
**파티로서 평가를 쌓아야** 오릅니다.

```
가상 파티      등급 없음 → 자격이 걸릴 기준이 없음 (누구나 모일 수 있음)
정규 등록 직후  등급 최하 → 사실상 제한 없음
평가를 쌓아 B급 → 가입 자격 D 이상 → F급은 못 들어옴
```

주인님이 말씀하신 **"B + B + F는 되도록 안 돼야 한다"** 가 여기서 그대로 나옵니다
("파티등급이 세워지면 … 최소한 파티 등급의 −2등급까지만 허용되거나 그런식으로").
**등급이 세워진 뒤에 걸리는 제한**이라는 것이 중요합니다 — 그래서 첫 파티가 막히지 않습니다.

> **순환 참조 문제가 없습니다.** 이전에 이 문서에는 "파티 등급 = 최고 개인 등급 + 1"이라고
> 적혀 있었는데(**에이전트 안, 폐기**), 그것 때문에 "첫 파티는 기준 등급이 없다"는
> 순환이 생겼습니다. 파티 등급이 독립적으로 쌓이고 최하에서 시작하니 문제가 사라집니다.

### 6.3 파티 등급이 여는 것 — 파티 전용 의뢰

**개인으로는 아예 못 받는 의뢰**가 여기 들어갑니다.

랭크가 셋인데 서로 겹치지 않습니다.

| 랭크 | 무엇을 여나 |
|---|---|
| **길드 랭크** | 의뢰가 **얼마나 많이, 얼마나 좋은 게** 뜨는가 (§17.8, §17.10) |
| **개인 등급** | 혼자·임시 조합으로 받을 수 있는 **난이도** |
| **파티 등급** | **파티 전용 의뢰** |

§17.8의 "랭크가 오르는 체감 = 새로운 게 보이기 시작한다"와 같은 결입니다.

그리고 사다리가 하나 생깁니다.

```
개인 의뢰  →  파티 전용 의뢰  →  …  →  마왕
```

레이드·던전·마물령 침범처럼 여러 명이 필요한 일이 자연스럽게 파티 전용으로 갑니다.
최종 목표도 당연히 파티 의뢰입니다.

**그리고 이것이 길드 성장의 실체가 됩니다.** 한 사람은 정규 파티 하나이므로, 파티
전용 의뢰를 여럿 굴리려면 **정규 파티를 여러 개 만들어야** 합니다. 길드가 커진다는 게
"사람이 늘었다"가 아니라 **"파티가 늘었다"** 가 되고, 각 파티가 6개월씩 쌓아야 하므로
규모가 시간을 요구합니다.

### 6.4 [검토중] 남은 것

| 무엇 | 비고 |
|---|---|
| **파티 평가가 무엇으로 얼마나 쌓이는가** | 의뢰 난이도·성공 건수쯤일 텐데 수치는 시뮬레이션 대상 |
| 솔로잉 해금 등급 | 주인님 발언은 "C등급이나 D등급부터". **에이전트가 C로 확정한 것은 승인 안 됨** |
| 승급 의뢰의 세부 | 자격 조건 · 실패 시 재도전 · 파티 승급과 개인 승급이 같은 형태인지 (§6.5) |
| 국가 지원 기간 | 1년 단위 육성 전제로 잡은 5년이라 재검토. §7에서 |

### 6.5 승급 — 승급 의뢰로 [확정]

**파티든 개인이든 승급 의뢰를 통과해야 오릅니다.**

- 그 의뢰는 **길드에 도움이 되는 수준**입니다. 보수와 명성이 따라오므로
  승급이 순수 비용이 아니고, 미룰 이유가 없습니다
- **지속 의뢰입니다.** §17.8의 "그 달에 안 받으면 사라진다"에 해당하지 않습니다 —
  준비가 안 된 달에 떠서 놓치는 일이 없어야 하기 때문입니다

승급이 **자동이 아니라 사건**이 됩니다. 숙련도가 문턱을 넘는 순간 조용히 올라가는 게
아니라, "이제 올릴 때가 됐다"고 판단해서 의뢰를 받고 통과해야 합니다.

**[검토중]** 승급 의뢰의 자격 조건(숙련도 문턱이 있는지) · 실패 시 재도전 규칙 ·
파티 승급과 개인 승급이 같은 형태인지.

#### 이 방식이 푸는 문제

지금 등급은 **숙련도 숫자 하나**로 정해집니다. 그래서 `03-formulas.md` §6.5에 적어둔
문제가 생깁니다 — **훈련만 5년 해도 3등급이 됩니다. 돈을 한 푼도 안 벌어온 사람이요.**

승급 의뢰는 실전을 요구하므로 이게 자동으로 막힙니다.

#### 아래는 [제안] — 승인 안 됨

이전에 에이전트가 적어둔 안입니다. 승급 의뢰로 대체됐으므로 **인용하지 마세요.**

실적 조건을 붙입니다.

```
승급 조건 = 숙련도 (자격)  +  실적 (조건)

예: D → C   숙련도 45 이상  AND  난이도 3 이상 의뢰 5건 완수
```

이러면 등급이 다시 **"그 사람의 가치"**가 됩니다.
[01-game-design.md](01-game-design.md) §3.6의 원래 설계가 그것이었는데,
지금은 숙련도의 다른 이름일 뿐입니다.

> 구체적인 문턱(숙련도 값, 필요 의뢰 수와 난이도)은 배치 시뮬레이션으로 잡습니다.
> 8단계 × 두 조건이라 감으로 정하면 어딘가 반드시 막힙니다.

### 6.6 동행 조건이 사는 이유

- **파티가 실체가 됩니다.** 그냥 두면 파견마다 즉석 조합이라 "파티"라는 개념이 없습니다
- **무기한 게임에 중기 목표가 생깁니다.** "이 셋으로 반년 굴려 정규 파티를 만든다"가
  매달의 선택을 묶습니다
- **함께 나간 달만 세므로** 육성이냐 실전이냐의 선택에 무게가 하나 더 붙습니다

> **폐기됨** — 이 문서에는 "한 명이 죽으면 3년 쌓은 파티 랭크를 잃는다"고 적혀 있었습니다
> (**에이전트 안**). 실제 규칙은 **1명이 남을 때까지 해체되지 않음**이므로, 죽음의 대가는
> 랭크 소멸이 아니라 **증원에 다시 6개월이 걸리는 것**입니다. 훨씬 부드럽습니다.

### 등급 −2 제한이 막는 것

제한이 없으면 **캐리 태우기가 최적해**가 됩니다. A급 파티에 신입을 끼우고 A급 의뢰를 돌면
신입은 위험은 낮은데 숙련도 15/년과 판단력 +6을 그대로 챙깁니다.

**순환 참조 주의** — 가입 자격은 **가입 시점의 파티 등급**으로 판정합니다.
가입 후 파티 등급이 올라도 기존 멤버는 남습니다. 안 그러면 파티가 성장할 때마다 자기 멤버를 뱉어냅니다.

### 그래서 생기는 구조 — 1군과 2군

```
1군   A급 파티 — 어려운 의뢰, 수입 담당
2군   F급 파티 — 신입 둘, 쉬운 의뢰로 경험 축적
      3년 뒤 D급쯤 되면 1군 결원 시 승격
```

**신입은 항상 둘씩 뽑아야 합니다.** 1군이 올라간 뒤엔 신입이 거기 못 들어가고,
최소 2인 규칙 때문에 혼자서도 못 나갑니다.

그 결과 **길드 규모가 자연스럽게 커지도록 강제됩니다.**
유지비가 인원 비례이므로 압박도 함께 커집니다 —
**연봉으로 쥐어짜는 게 아니라 구조가 인원을 요구하는** 형태입니다.

### 등급 표기 충돌

```
무기 적성    E D C B A S        (6단계)
모험가 등급  F E D C B A S SS   (8단계)
```

같은 글자가 다른 뜻입니다. 화면에 `A` 하나만 뜨면 구분이 안 됩니다.
**표기로 가르는 것**(`적성 A` / `A급 모험가`)이 싸고 충분합니다.

**칭호가 35개 → 56개**가 됩니다 (등급 8 × 무기 7). 21개를 새로 지어야 합니다.
아트가 없는 게임에서 **텍스트가 곧 얼굴**이라 대충 지으면 티가 납니다.

## 7. 경제 구조 — 연봉에서 유지비 + 분배로

### 지금 무엇이 어긋나 있는가

- **훈련생에게 고액 연봉을 줍니다.** 15세 신입이 1년 훈련하면 연봉 60을 받습니다
- **훈련만 해도 연봉이 오릅니다.** 숙련도가 훈련으로 연 9씩 붙어 5년이면 3등급(연봉 340).
  **돈을 한 푼도 안 벌어온 사람의 몸값이 5배 뜁니다**
- **그래서 훈련이 이중으로 손해입니다.** 게임의 절반이 육성인데 육성할수록 벌이가 나빠집니다

장르 관례와도 어긋납니다. 모험가는 월급쟁이가 아니라 **의뢰 보수를 나누는** 쪽입니다.

### 바꿀 것

```
유지비     1인당 연 40 (등급 무관, 숙식비)
보수 분배  의뢰 보수를 길드와 모험가가 나눔. 파티 평균 등급이 높을수록 모험가 몫이 큼
```

| 파티 평균 등급 | 모험가 몫 | 길드 몫 |
|---|---|---|
| 1 (견습) | 30% | 70% |
| 3 | 46% | 54% |
| 5 | 60% | 40% |

**얻는 것**

- 훈련생은 밥값만 듭니다
- 강한 사람은 여전히 비싸지만 **일을 시켰을 때만** 비쌉니다
- **경영 판단이 생깁니다.** 지금은 "무조건 제일 센 애를 보낸다"가 정답인데,
  분배제가 붙으면 **"이 의뢰엔 누구를 보내는 게 남는가"**가 생깁니다.
  쉬운 의뢰에 고수를 보내는 건 손해입니다

### 압박은 어디서 오는가

유지비가 싸지면 "놀리면 손해"가 사라져 **다시 훈련만 시키는 게 정답**이 됩니다.
그래서 압박을 **의뢰 실적**으로 옮깁니다.

```
국가 지원 — 창설 후 5년간 무상. 조건 없음. 6년차부터 없음
            앞의 2년은 튜토리얼과 준비 기간이라 실질 3년
```

처음에는 "실적 연동 + 점감"을 제안했지만 **둘 다 필요 없어졌습니다.**

**절벽이 없습니다.** 연봉을 없앤 덕분입니다.

```
연봉 체계였다면   5년 훈련 → 3등급 4명 → 6년차 급여 1,360/년   ← 절벽
유지비 체계에서   40 × 4명 = 160/년                            ← 절벽 아님
```

유지비는 등급 무관이라 몸집을 키워도 안 오릅니다.

**"안전하게만 키우기"도 구조가 막습니다.**

- 파티 랭크는 **실전 연도만** 카운트 → 훈련만 하면 파티가 영영 안 만들어짐
- 숙련도가 실전 15 vs 훈련 9 → **실전이 66% 빠름**
- 승급에 **실적 조건**이 붙음 → 훈련만으로는 등급이 안 오름

**놀면 손해라는 게 돈이 아니라 구조에서 나옵니다.** 돈으로 쥐어짜는 것보다 낫습니다.

### 미해결

- 훈련에 비용(시설 사용료·교관)을 붙일지. **안 붙이는 쪽 권장** — 12개월 계획에
  이미 능력치·피로·컨디션·실패 확률이 얹혀 있어 돈까지 넣으면 한 달 고르는 부담이 너무 커집니다.
  나중에 시설 투자로 붙이는 게 낫습니다
- 초기 자금과 국가 지원 액수. 유지비·계약금·의뢰 보수를 함께 재야 정해집니다

## 8. 계약 구조 — "한 판"에서 "목표를 채우는 것"으로

지금 의뢰는 **전투 한 판**입니다. 적 수는 `난이도/2 + 1`로 정해집니다.

"고블린 10마리"는 다릅니다. 한 판에 10마리를 세우면 전열/후열이 무너지므로
**3~4마리씩 여러 판**이 됩니다.

### 다전투가 살리는 것

> **판 사이에 회복이 안 되고 자원이 깎여야 짐꾼과 포션이 의미를 갖습니다.**

지금은 전투가 한 판이라 포션 2개를 다 쓸 일이 거의 없습니다.
짐꾼 역량(`ContractSupport.ExtraPotions`)도 구현돼 있는데 **사실상 죽은 기능**입니다.

**고블린 10마리라는 목표 하나가 짐꾼 역할 전체를 살립니다.**

## 9. 장비 · 포션 — 최소만

### 무기

지금 `EquippedStyle`은 enum 필드고 모집 시점에 이미 박혀 있습니다.
**무기 없는 상태 자체가 표현되지 않습니다.**

튜토리얼에 필요한 것만:

- `EquippedStyle`을 nullable로 (맨손 허용)
- 맨손 전투 처리 (위력 배율 낮게)
- 나무검 지급 이벤트

> ⚠️ **여기서 멈추기가 어렵습니다.** 무기가 물건이 되는 순간 구매·상점·대장장이 제작·
> 인벤토리·무기 등급이 줄줄이 따라옵니다. **장비 시스템은 별도 항목으로 뺍니다.**

### 포션 — 비율에서 고정 수치로

지금은 `최대 HP × 35%`입니다. 고정 수치로 바꾸면 **초반엔 강하고 후반엔 종잇장**이 되므로
**등급이 필수**가 됩니다.

| 등급 | 회복량 | 쓸 만한 구간 |
|---|---|---|
| 일반 | 50 | 초반 (HP 200~400) |
| 상급 | 250 | 중반 |
| 최상급 | 1,000 | 후반 |

`docs/08` #2의 "회복약이 과하다"는 **고정 수치로 바꾸면 후반에는 자동 해결되고 초반에는 더 심해집니다.**

튜토리얼에는 일반 포션 하나만 있으면 되므로 지금 다 만들 필요는 없습니다.

## 10. 스킬 체계 — [확정]

> 2026-07-29 대화에서 정리. 표기 없는 항목은 전부 **[확정]** 입니다.

**지금의 스킬 관련 구조는 전부 새로 짭니다.** 주인님 입장이 "어쨌든 전부 새로
다 개편해야 한다"입니다. 아래 기존 코드는 **재활용할 자산이 아니라 참고할 선례**입니다.

### 10.0 패시브와 액티브가 다르게 다뤄집니다

| | 슬롯 | 왜 |
|---|---|---|
| **패시브** | **없음. 가진 것 전부 적용** | 전투에 도움이 되는 것도 있고 아닌 것도 많아서 골라 낄 성질이 아님 |
| **액티브** | **있음. 골라서 장착** | 이게 빌드를 만듭니다 |

**액티브 슬롯 수는 직업 데이터에 들어 있습니다.** 견습검사와 검성이 서로 다른 슬롯
수를 가집니다 — 별도의 "직업 숙련" 축이 있는 게 아니라, **직업 표의 한 열**입니다.

**액티브는 특정 무기를 장착해야 쓸 수 있습니다.** 이것이 §16의 "궁수가 창을 들 수
있지만 손해"를 실제 규칙으로 만듭니다 — 창을 들면 궁수 액티브가 통째로 죽습니다.

> **부수 효과 — 전술 규칙 부풀기가 여기서 막힙니다.**
> 직업이 수십 종이어도 한 캐릭터가 다루는 액티브는 슬롯 수만큼입니다.
> 전술 규칙에서 고를 행동도 그만큼이라, 규칙 짜기가 노동이 되지 않습니다.
> FF12 감빗이 호불호가 갈렸던 지점을 슬롯이 자동으로 막아줍니다.

### 10.0b 자원 — 마나 + 쿨다운 둘 다

**"마구잡이로 쓰면 전략의 요소가 줄어듭니다."**

- **자원은 마나 하나로 통일**합니다. 기력 같은 걸 따로 만들지 않습니다.
- 대신 **소모량이 스킬마다 다릅니다.** 전사 기술은 싸고 마법은 비쌉니다 —
  "전사가 마나를 엄청 쓰면서 싸우는 직업은 아니니까요."
- **쿨다운도 함께** 둡니다.

> **근거 데이터** (300회 × 6년 육성, 999 스케일 전환 전이라 절대값은 무효·비율만 유효)
>
> | 방침 | 정신 | 마나 (= 정신×2 + 지능×1) |
> |---|---|---|
> | 마법 | 50 | 150 |
> | 균형 | 30 | 90 |
> | 전위 · 유격 · 무예 | **12** | **36** |
>
> 특화로 밀면 정신이 시작값 근처(12)에 머뭅니다. 균형으로 키우면 명상이 섞여 30까지
> 오릅니다. **전사와 마법사의 마나 격차가 약 4배**이므로, 물리 기술의 소모량을
> 그만큼 낮춰야 전사도 쓸 수 있습니다.

### [방향] 2축 구조

성격도 스킬의 한 갈래로 둡니다 — 성격 오라와 패시브 스킬은 하는 일이 같기 때문입니다.
따로 만들면 효과 계산·표시·밸런스 표를 두 벌 짓게 됩니다.

|  | 패시브 | 액티브 |
|---|---|---|
| **태생** | 성격 오라 · 성장 성향 | 거의 비어 있음 |
| **직업** | 역할 강화 | **주력** |

**효과 표현은 공유하고 획득 규칙은 분리합니다.** 셋이 정반대라서 한 그릇에 못 담습니다.

| | 태생 | 직업 |
|---|---|---|
| 획득 | 타고남. 플레이어 통제 밖 | 육성의 보상. 플레이어가 통제 |
| 제거 | 불가 | **액티브만** 교체·미장착 |
| 대상 | 파티 전체(오라)일 수 있음 | 보통 자신 |

갈라두지 않으면 **"성격을 훈련으로 바꿀 수 있나"** 에 답할 수 없습니다.
예라면 성격이 정체성이 아니게 되고, 아니라면 왜 같은 시스템인지 설명이 안 됩니다.

### 10.2b 직업 패시브는 전직해도 남습니다 [확정]

**"직업 패시브만 먹고 갈아타기 가능합니다."**

그래서 **여러 직업을 훑는 것이 하나의 육성 방식**이 됩니다. 오래 산 캐릭터일수록
패시브가 두꺼워지고, 그게 장기 육성의 보상이 됩니다. 전직에 비용이 없다는 §16.4와도
어긋나지 않습니다.

### [제안] 밸런스 축 — 승인 안 됨

태생은 **약하지만 파티 전체**, 직업은 **강하지만 자신**. 이러면 좋은 성격을 타고난
캐릭터가 육성 성과를 압도하는 문제를 막을 수 있습니다.

### [확정] 스킬이 떠맡게 된 것 — §16에서 넘어옴

**지금 무기 스타일이 갖고 있는 능력이 전부 스킬로 넘어옵니다.**
무기에는 위력·속도·사거리만 남습니다 (§16.2).

| 지금 `StyleCapability`에 있는 것 | 어디로 |
|---|---|
| `CanHeal` 회복 | **스킬** |
| `CanTaunt` 도발 | **스킬** |
| `HitsMultipleTargets` 광역 | **스킬** |
| `UsesMagic` 마법 | **스킬** |
| `CanStrikeBackRow` 후열 타격 | **스킬** — "관통 사격" 같은 걸 배워야 함 |
| 치명타 확률·배율 특성 | **숙련도로 얻는 패시브 스킬** |

마지막이 특히 중요합니다. 초보가 쌍수를 들었다고 바로 치명타가 자잘하게 잘 터지는 건
이상합니다 — **그 무기를 오래 써서 얻은 것**이 맞습니다.

### [확정] 직업 스킬의 습득 경로

§16이 정해졌으므로 풀렸습니다. **직업이 스킬을 주고, 직업은 숙련도 조합으로 해금**됩니다.
직업 하나 = `{ 이름, 요구 숙련 조합, 주는 스킬, 숙련도 보정 }` 한 줄이므로,
**스킬 묶음도 같은 데이터에 얹힙니다.**

### [검토중] 미결

| 무엇 | 비고 |
|---|---|
| **직업 하나가 주는 스킬 개수** | 주인님: "좀 고민해봐야할 것 같아요". **직업 수와 반비례합니다** — 잘게 쪼개면(화염술사·빙결술사·뇌전술사) 직업당 스킬이 적어도 되고, 크게 묶으면(마법사 하나) 많이 줘야 고르는 재미가 생깁니다. 어느 쪽이든 데이터 표에 행을 넣는 일이라 작업량 차이는 생각보다 작을 수 있습니다 |
| 액티브 슬롯 수 | 예시로 5칸이 나왔으나 확정 아님. 직업마다 다름 |
| 태생 스킬 개수와 풀 크기 | 성격 "36가지"의 실제 형태 |
| 기존 `Temperament` 3종 | 성장 성향을 태생 패시브로 흡수할지 |
| 스킬 개수 상한 | 상태 효과를 7종으로 묶어둔 것과 같은 이유로 **상한을 정하고 시작해야 함** |
| 쿨다운 단위 | 라운드 기준인지 |
| 스킬 자체의 성장 | 배우면 끝인지, 쓸수록 세지는지 |
| 이해도 공개 확률 곡선 | 중요한 스킬일수록 늦게 드러나게 하는 방식 (§16.7) |
| 물리 기술의 마나 소모량 | 999 스케일 전환 뒤에 다시 재야 함 |

## 16. 직업 — [확정]

> 2026-07-29 대화에서 정리. 표기 없는 항목은 전부 **[확정]** 입니다.

### 16.1 직업은 무기와 별개 축

**직업 ≠ 무기.** "창을 낀 궁수"도 이론상 나올 수 있는 구조입니다.
직업이 무기 사용을 **제한하지 않습니다** — 가능하지만 손해라서 대부분 안 할 뿐입니다.

### 16.2 다섯 축의 분담

**서로 겹치지 않게 나눕니다.** 축이 중복되면 하나가 죽습니다.

| 축 | 무엇을 정하나 |
|---|---|
| **무기** | **위력 · 속도 · 사거리. 그게 전부입니다.** |
| **숙련도** | 그 무기를 오래 써서 생기는 것 (치명타 특성 등) |
| **스킬** | **할 수 있는 행동** — 회복 · 도발 · 광역 · 후열 타격 |
| **직업** | 숙련도 보정 + 배우는 스킬 + **액티브 슬롯 수** |
| **적성** | 그 무기 숙련도가 빨리 오르는 재능. **캐릭터가 타고납니다** |

**"직업 숙련"이라는 별도 축은 없습니다.** 슬롯 수는 직업 데이터의 한 열입니다.

> ⚠️ **지금 코드는 이렇지 않습니다.** `StyleCapability`가 회복·도발·광역·마법·후열타격·
> 치명타 특성을 전부 무기 스타일에 물려두고 있습니다. **전부 이동 대상입니다.**
> 초보가 쌍수를 들었다고 바로 치명타가 자잘하게 잘 터지는 건 이상합니다 —
> 그건 무기의 성질이 아니라 **오래 써서 얻은 것**입니다.

### 16.2b 무기는 손에 듭니다 — 주무기 / 보조무기 × 좌 / 우

**무기 칸이 넷입니다.** 주무기(오른손·왼손), 보조무기(오른손·왼손).

> **부수 효과 — 무기 스타일 열거형이 사라집니다.**
> 지금 `WeaponStyle` 7종(한손+방패, 쌍수, 양손, 활, 석궁, 지팡이, 창)이 코드에 박혀
> 있는데, **손 배치가 곧 스타일**이 됩니다.
>
> | 손 배치 | 결과 |
> |---|---|
> | 오른손 검 + 왼손 방패 | 한손+방패 |
> | 오른손 검 + 왼손 검 | 쌍수 |
> | 양손 다 차지 | 양손무기 · 활 · 지팡이 |
>
> 새 무기를 추가해도 열거형을 안 건드립니다. §16.6의 데이터 주도 요구와 맞물립니다.

**주무기 ↔ 보조무기 전환은 턴을 하나 씁니다.**

이게 없으면 §10의 "액티브는 특정 무기를 장착해야 쓸 수 있다"가 무의미해집니다 —
아무 때나 바꿔 들 수 있으면 제약이 아니기 때문입니다.

그리고 **조합 직업 문제가 여기서 풀립니다.** 마궁사가 주무기에 활, 보조에 지팡이를
들면 양쪽 스킬을 다 쓸 수 있습니다. 대신 전환할 때마다 턴을 내주므로 공짜가 아닙니다.

### 16.2c 계급(`JobRank`)이 직업 표에 흡수됩니다

견습검사 → 검사 → 쌍검사 → 명검객 → 검성은 **요구 숙련만 다른 직업 행**입니다.
별도의 계급 축이 필요 없습니다.

> ⚠️ 지금 `JobRank` 열거형(견습~대가 5단계)에는 **연봉과 수주 가능 난이도까지 걸려
> 있습니다** (`JobRanks.AnnualWage`, `MaxContractDifficulty`). 이것들도 직업 데이터로
> 옮겨야 합니다. 축이 하나 줄어드는 것이므로 오히려 단순해집니다.

### 16.3 시작 — 희망 직업

- 모집할 때 **캐릭터가 희망 직업을 가지고 옵니다.** 플레이어가 배정하는 게 아닙니다.
- 직업에 따라 **살짝의 숙련도 보정**이 붙습니다.
- **희망과 적성이 어긋날 수 있습니다.** 그 어긋남이 전직의 동기입니다.

### 16.4 전직 — 자유

- **조건 없음, 비용 없음.** 언제든 바꿀 수 있습니다.
- 대가는 규칙이 아니라 자연히 생깁니다 — 새 무기 숙련은 0부터입니다.
  **"신궁이었던 애가 검사로 전직한다고 검성이 되진 않습니다."**
- 그래서 **늦게 알아챌수록 손해**이고, 그게 이해도에 투자할 이유가 됩니다.

### 16.5 히든 직업 — 숙련 조합으로 해금

**직업은 숙련도 조합의 함수입니다.**

```
캐릭터가 가진 것: 무기별 숙련도 (활 90 · 지팡이 60 · 검 10 …)
                        ↓
              직업 해금 조건표와 대조
                        ↓
   활 90              → 신궁
   활 60 + 지팡이 60  → 마궁사   ← 히든
```

- 조건을 만족하면 **해금**됩니다. 자동 전직이 아니라 플레이어가 시킵니다.
- **조합 직업은 평균이 아니라 합집합입니다.** 양쪽 직업이 각각 가진 장점을 흡수합니다.
  "다들 노력은 보상받아야 좋은 거니까요."
- 대가는 **시간**입니다. 두 숙련을 올리는 데 배로 걸리고, 그동안 그 캐릭터는 오래
  어중간합니다. 경력이 유한하므로 못 닿을 수도 있습니다.

덤으로 계급 문제가 풀립니다 — **칭호가 가진 숙련 조합에서 나오므로**, 검사로 전직해도
활 숙련 90은 사라진 게 아니라 **조합의 재료**로 남습니다.

### 16.6 데이터 주도 구조 — 설계 요구사항

**직업은 수십 종이 될 예정입니다.** 복수 무기를 쓰는 직업까지 포함해서요.
전부 설계하지는 않되 **추가되기 쉬운 구조**여야 합니다.

직업 하나 = 표의 한 줄:

```
{ 이름, 요구 숙련 조합, 주는 스킬, 숙련도 보정 }
```

> ⚠️ 지금은 `WeaponStyle`이 **열거형에 박혀 있고** 능력표도 코드에 하드코딩돼 있어
> 하나 추가할 때마다 코드를 고쳐야 합니다. 직업이 수십 종이면 이 방식으론 안 됩니다.
> CLAUDE.md의 "밸런스 수치를 데이터로 분리" 원칙이 여기서는 **수치가 아니라 구조**에
> 적용됩니다.

### 16.7 이해도 — 캐릭터를 알아가는 척도

**주인공이 그 캐릭터를 얼마나 아는가.** 캐릭터마다 따로 쌓입니다.

- **한 달 육성에 +1%** (12%/년, 8년쯤에 100%)
- **멘토가 있으면 더 빠릅니다.**
- **멘토와 숨은 특성이 같으면 더더욱 빠릅니다** — 겪어본 사람이 알아봅니다.
  재밌는 건 **특성을 모르는 상태에서 멘토를 붙여야 한다**는 점입니다.
  알고 나서 붙이면 이미 늦었으므로, 직감으로 붙이고 맞으면 빨리 드러납니다.
- 숨은 특성·특화 패시브가 **확률적으로 하나씩 공개**됩니다. 중요한 것일수록 늦게.
  스킬마다 확신도 메시지를 붙이면 감당이 안 되므로 확률 공개로 갑니다.
- **50%쯤에서 숨은 것의 개수가 보입니다.** 그 전까지는 막연하고,
  그 뒤로는 목표가 생깁니다 — **전반은 발견, 후반은 수집**.

이해도가 전직 판단의 재료이자 고리의 중심입니다.

```
활 적성 S (타고남 · 숨겨져 있음)
   ↓ 이해도가 오르면 드러남
"활에 재능이 있는데"
   ↓
현재 직업: 검사 ← 희망 직업이 그거였으니까
   ↓
"아무리 봐도 칼하고는 안 어울리는데" → 전직
```

**재능이 숨어 있지 않으면 이 고리가 안 돕니다.** 처음부터 "활 S"가 보이면
그냥 궁수 시키면 끝입니다.

> **기존 `ScoutingReport.Confidence`(확신도)의 진화형입니다.** 지금 것과 두 군데 다릅니다 —
> 오르는 방식(점근형 → 선형)과, 무엇을 여는가(평가서 정확도만 → **특성·패시브 해금**).
> 두 번째가 큰 변화입니다. 이해도가 **캐릭터를 실제로 강하게 만들므로**,
> 오래 데리고 있을 이유가 생기고 영구사망의 무게도 같이 올라갑니다.

### 16.8 특성이 플레이어 지시를 막을 수 있다

희망 직업을 무시해도 기본적으로는 그냥 따릅니다 — 길드마스터의 추천에는 이유가
있다고 여기기 때문입니다. 다만 **고집 같은 특성**이 있으면 얘기가 달라질 수 있습니다.

전투 쪽과 짝을 이룹니다.

| 언제 | 무엇이 지시를 막나 |
|---|---|
| 전투 중 | 상태이상 (공황 등) |
| 육성 중 | **태생 특성 (고집 등)** |

태생 패시브가 수치 보정만이 아니라 **지시를 제약하는 역할**도 한다는 뜻입니다.

### 16.8b 짐꾼 — 비전투 직업 [확정]

**짐꾼은 직업입니다.** 주 역할은 파티 보조(서포터)입니다.

#### 판별 기준 — 파티 구성에 꼭 필요한가

정찰병·감정사·채집꾼은 **모험가 직업이 아닙니다.** 있으면 좋지만 없어도 파티가
굴러갑니다. 짐꾼은 **없으면 안 됩니다** — 그게 차이입니다.

#### 가방이 손 칸을 차지합니다

짐 용량은 근력이 아니라 **가방**이 정합니다. 짐을 드는 것 자체는 근력만 있으면
누구나 하는 일이라, 그것만으로는 직업이 성립하지 않습니다. 대신 §16.2b의 손 칸을 씁니다.

- **가방은 양손을 차지합니다.**
- **가방을 들면 보조무기 칸을 쓸 수 없습니다.** 즉 전환할 무기가 없습니다.
- 그래서 **짐꾼은 그 파견 동안 무방비입니다.**

이것이 만드는 것들:

| | 결과 |
|---|---|
| 짐 용량이 공짜가 아님 | 칸을 내줘야 하므로 근력 좋은 전사가 겸할 수 없음 |
| **비전투 요원이 성립** | 정말 못 싸우는 사람이 생기고, 그게 플레이어의 선택 |
| **짐꾼은 파티가 지켜야 하는 존재** | 호위 대상이 파티 내부에 생김 |
| 데려가는 것이 진짜 비용 | 짐은 많이 들지만 한 사람을 지켜야 함. 안 데려가면 치료제를 못 챙김(§18.6) |

**짐꾼 직업의 액티브는 가방을 요구합니다** — §10의 "액티브는 특정 무기를 요구한다"와
같은 규칙입니다. 예외를 만들지 않습니다.

#### 표적 선정 — 짐꾼만 노리지 않습니다

**짐꾼은 가장 안전한 위치에서 서포팅하는 것이 규칙**이므로, 마물이 짐꾼만 골라
때리는 형태는 두지 않습니다.

> ⚠️ 지금 `TacticalBrain`에 "가장 약한 적을 공격"(`AttackWeakest`)이 있어서,
> 그냥 두면 마물이 짐꾼을 최우선으로 칩니다. **짐꾼은 표적 선정에서 최후순위** —
> 다른 아군이 하나라도 서 있으면 노려지지 않습니다.
> 상태 효과인 은신과 달리 **짐꾼의 상시 성질**입니다.

#### 짐을 잃는 조건

| 상황 | 짐 |
|---|---|
| 짐꾼만 쓰러짐 | **남습니다** |
| 파티 전멸 | **잃습니다** |
| 후퇴 (§17.5) | 전멸이 아니므로 **남습니다** — 손절하면 물건은 지킴 |

#### 파티 규칙 — §6으로 넘김

짐꾼 최대 1명 · 짐꾼만으로 파티 구성 불가 · 짐꾼 솔로잉 금지.

#### 튜토리얼과의 연결

주인공이 튜토리얼에서 하는 일이 정확히 짐꾼 역할(위기마다 포션 지급)인데,
**주인공은 죽지 않습니다**(§11). 그래서 튜토리얼에서는 짐꾼의 위험을 못 느끼고,
이후 실제 짐꾼을 데려가면서 배웁니다. 안전하게 역할을 익히고 그다음에 대가를 아는
순서라 학습 곡선이 자연스럽습니다.

#### [검토중]

- 가방 하나당 용량, 그리고 근력이 관여하는지
- 한손짜리 작은 배낭을 나중에 넣을지 (무기 표에 한 줄 추가하면 되므로 언제든 가능)
- 짐꾼 액티브의 내용 (아이템을 남에게 쓰기 · 아군 감싸기 등)

### 16.8c `SupportSkill` 5종은 폐기합니다 [확정]

감정 다섯이 무기 숙련과 별개 축으로 있는데, **그런 개념은 설계에 없습니다.**

전투에 도움이 되는 것도 안 되는 것도 있는 패시브는 §10의 스킬 체계가 이미 담당합니다.

### 18.4 지속 피해 넷의 차이 — 커지는 조건으로 가릅니다

**넷 다 자연 해제가 없습니다.** 치료해야 풀립니다(§18.5). 그래서 "짧다/길다"로는
구분할 수 없고, **무엇 때문에 나빠지느냐**로 갈립니다.

| 이름 | 커지는 조건 | 플레이어의 판단 |
|---|---|---|
| **중독** | **다시 걸릴 때** (스택) | 스택이 쌓이기 전에 저놈을 정리할까 |
| **출혈** | **행동할 때마다** | 지금 지혈할까, 한 턴 더 버틸까 |
| **화상** | 안 커짐 (고정) | 총량이 얼마인지 계산 |
| **동상** | 안 커짐 + 느려짐 | 속도를 포기하고 갈까 |

중독과 출혈이 둘 다 "커진다"이지만 **원인이 정반대**라 겹치지 않습니다.
중독은 적이 반복해야 위험해지고, 출혈은 한 번만 걸려도 방치하면 위험해집니다.

**출혈이 특히 이 게임과 맞습니다.** 포지션 이동도 행동이라, 출혈 걸린 사람을 후열로
빼려면 피가 더 납니다. 그리고 **"행동할 때 커진다"는 규칙 한 줄이 전투 안팎을 모두
해결합니다** — 전투 중에는 매 턴 행동하니 계속 커지고, 전투가 끝나면 행동이 없으니
저절로 멈춥니다. 별도 규칙이 필요 없습니다.

#### 임계 전이 — 동상만 씁니다

동상이 쌓이면 **빙결**로 넘어가고, 빙결이 풀릴 때 동상도 같이 풀립니다.
파국이자 리셋이라 완전히 절망적이지 않습니다.

이게 없으면 동상은 "귀찮지만 참을 만한" 상태가 되어 치료제를 안 쓰게 됩니다.
위협선이 있어야 언제 치료할지가 판단이 됩니다.

> **이걸 동상만의 특권으로 두지 않습니다.** "임계에 닿으면 어떤 상태로 전이한다"를
> **매개변수로 두고 동상만 값을 채웁니다.** 그러면 "중독이 쌓이면 마비 아닌가요"
> 같은 요구가 따라와도 일관성이 깨지지 않고, 나중에 필요하면 값만 넣으면 됩니다.

### 18.5 전투가 끝나면 — 상처는 남고 상태는 풀립니다

> **몸에 난 것은 남고, 상황이 만든 것은 상황이 끝나면 풀린다.**

| 남음 (치료해야 풀림) | 사라짐 (라운드 경과 · 전투 종료) |
|---|---|
| 중독 · 화상 · 출혈 · 동상 · **마비** · **석화** · 저주 | 수치 증감 · 빙결 · 속박 · 침묵 · 공포 · 혼란 · 도발 · 은신 · 보호막 · 재생 |

왼쪽은 **상처**고 오른쪽은 **상태**라 따로 외울 필요가 없습니다.

> **정정** — 이 표에 처음에는 마비가 "사라짐" 쪽에 있었습니다(에이전트 분류).
> 그런데 **마비치료제가 있다면 자연 해제가 없어야** 일관됩니다. 신경이 상한 것이므로
> 상처 쪽이 맞습니다. 빙결은 치료제가 없고 동상에서 전이해 오는 것이므로 라운드로 풀립니다.

### 18.6 치료 수단

| 무엇 | 무엇을 푸나 |
|---|---|
| 해독제 | 중독 |
| 화상치료제 | 화상 |
| 지혈제 | 출혈 |
| 동상치료제 | 동상 |
| 마비치료제 | 마비 |
| **성수** | **석화 · 저주** |
| 정화 (스킬) | 석화 |

성수만 둘을 풉니다. 그리고 석화는 **스킬로도 아이템으로도** 풀리므로,
정화를 가진 사람이 파티에 없어도 막다른 길이 아닙니다 — 대신 성수를 챙겨야 합니다.
정화가 있으면 짐을 아끼는 셈이라, 그 자체가 편성 판단이 됩니다.

**[검토중] 짐 상한.** 이게 보급을 판단으로 만드느냐를 정합니다 — 넉넉하면 다 챙기면
되므로 §17.5의 "플레이어는 편성과 보급"이 무의미해집니다. 감으로 정할 게 아니라
**몇 개를 들 수 있을 때 "다 챙기기"가 최적해가 되는지 시뮬레이션으로 재야 합니다.**
999 스케일 전환 뒤에 잡습니다.

> ⚠️ 지금 코드에는 **짐 용량 규칙 자체가 없습니다.** `SupportSkill.Portering`에는
> "회복약을 더 들고 갑니다"라는 설명만 있고 수치가 없으며, 파견 시작 회복약 2개는
> 에이전트가 `FieldYearSession`을 만들면서 넣은 임의값입니다.

### 18.7 지시 불통 — §14 지휘가 여기서 풀립니다

**"특정 상태이상에 걸린 아군에게는 지시가 통하지 않는다"** 는 §14의 [확정] 사항인데
종류가 미정이었습니다. **공포와 혼란 둘입니다.**

그리고 마비가 좋은 대비를 이룹니다.

| | 무슨 일이 벌어지나 |
|---|---|
| 공포 · 혼란 | **지시를 안 듣습니다.** 엉뚱한 행동을 함 |
| **마비** | **지시를 듣는데 못 합니다.** 아무 일도 안 일어남 |

지휘하는 입장에서 답답함의 종류가 다릅니다 — 하나는 통제를 잃는 것이고 하나는
헛도는 것입니다. 주인공이 지휘자(§11)라는 걸 생각하면 둘 다 있는 게 좋습니다.

### 18.8 뺀 것과 그 이유

**나중에 다시 꺼내지 않도록 이유까지 적습니다.**

| 뺀 것 | 이유 |
|---|---|
| 광폭 | 상태이상이라기보다 **스킬**. 광전사가 쓸 법한 것 |
| 매혹 | **마물 상대라 명분이 없음.** 서큐버스가 있어도 마물에게 매혹을 느낀다는 게 애매 |
| 실명 | 섬광탄 말고 걸 만한 게 마땅치 않고, **회피 격차가 가장 결정적인 수치**라 과하게 셈 |
| 기절 | **HP 0의 전투불능과 겹침.** 부상의 기준이 기절이므로 별도로 둘 필요 없음 |
| 탈진 | **피로와 겹침.** 이미 육성·파견 양쪽에 피로 축이 있음 |
| 중상 (최대 HP 감소) | 부상 층은 기절로 시작하므로 불필요 |
| 표식 · 격리 | 도발·은신으로 충분. 축이 늘어날 만큼의 값이 없음 |
| 전염 | **"누군가가 걸고 안 걸고"** 기준에서 벗어남. 두 번째 감염자부터는 아무도 안 건 것이 됨 |
| 굶주림 · 갈증 | 피로와 겹침 |
| 흡혈 · 생명력 흡수 | 상태 효과가 아니라 스킬 효과 |
| 넘어짐 | 속박이나 속도 감소로 표현됨 |
| 무기 · 방어구 파손 | 방어구는 수치 증감으로 흡수. **무기 파손은 액티브 봉인**이라 성격이 다르지만, **장비 아이템 시스템이 생긴 뒤** 얘기 |

- **도적·산적은 있습니다.** 인간이지만 전쟁은 아니고, 호위 의뢰의 자연스러운 상대입니다.
- **최종 보스는 마왕.** 목표로만 두고 서사는 붙이지 않습니다 (§13 참조).

| 출처 | 내용 | 보상의 성격 |
|---|---|---|
| **나라 · 영주** | 주기적. 마물 토벌, 전선 수비, 마물령 침범 | 보수 |
| **마을 · 의뢰주** | 호위, 마을 주변 마물 정리, 채집(광물·약초), 농사 지원, 보수공사, 광산 | 보수 |
| **길드 자체** | 정찰·탐색, 던전 발견, 보물찾기 | **명성** — 길드가 자기 돈 들여 하는 투자 |

### 17.3 형태 4종 — 완료 판정으로 가름

**만들 것은 4개, 플레이어가 보는 종류는 얼마든지 늘어납니다.**
진행 규칙은 형태별로 하나씩만 짜고, 종류는 목표물과 장소만 갈아끼웁니다.

| 형태 | 그 기간 동안 하는 일 | 전투가 | 예 |
|---|---|---|---|
| **토벌** | 나가서 찾아 싸운다 | **목적** | 마물 정리, 레이드, 던전 공략 |
| **지킴** | 자리를 지키며 기다린다 | **방해** | 호위, 전선 수비, 농사 지원, 보수공사 |
| **수집** | 캐고 모은다 | 사고 | 약초·광물 채집, 마물 소재 |
| **발견** | 뒤진다. **못 찾을 수도** | 사고 | 정찰, 던전 발견, 실종자 수색 |

**"전투 없음"은 없습니다.** 마물이 언제든 올 수 있는 세계라 밭에 있든 성벽에 있든
싸울 수 있습니다. 농사·보수공사도 결국 **일종의 호위**입니다 — 지켜야 할 대상이 있고
기간 동안 버팁니다. 다른 건 무엇을 지키느냐와 얼마나 자주 습격받느냐뿐입니다.

**토벌은 만나는 것이 전제입니다.** 나가서 찾아 싸우는 일이므로 "못 찾았다"가 성립하지
않습니다. **안 만날 수 있는 것은 지킴**입니다 — 습격이 올 수도, 안 올 수도 있습니다.

지킴형이 특이한 이유가 여기입니다: **아무 일 없이 끝나는 게 성공**입니다.
토벌과 정반대라 플레이 감각이 확실히 갈립니다.

> ⚠️ 여기에 한때 "토벌은 안 만나면 진척이 없다"고 적혀 있었습니다 —
> **에이전트가 쓴 문장이고 주인님의 모델과 반대였습니다.** 그 문장을 근거로 토벌
> 조우 확률을 0.85로 두어, 끝까지 일했는데도 진척 미달로 실패하는 파견이 생겼습니다.

파티 구성도 여기서 갈립니다 — 작업 의뢰는 **"일할 사람 + 지킬 사람"** 으로 짜입니다.
비전투 역량(채집·짐꾼·정찰·감정)이 보조가 아니라 주역이 되는 자리입니다.

### 17.4 기간과 판정

- **기간 고정.** 1달이 기본, 2~3달, **1년짜리도 있습니다.**
- **조기 종료 없음.** 목표를 빨리 채워도 정해진 달만큼 작업합니다.
- **성공 / 실패 이분법.** 부분 성공도 초과 성과도 없습니다 — 복잡해지기 때문입니다.
- **목표 수량은 달성 전제로 잡습니다.** 관리해야 할 할당량이 아니라
  **그 의뢰의 강도 표시**입니다. "고블린 10마리"는 그 기간에 그 정도 싸움이 있다는 뜻입니다.

> **[제안] 구현 판정 — 에이전트 안이며 승인되지 않았습니다.**
> (§17 서두가 "표기 없는 항목은 전부 [확정]"이라 했으므로, 표기 없이 두면 주인님의
> 결정으로 읽힙니다. 실제로 그렇게 들어갔던 것을 리뷰가 잡았습니다.)
>
> **이 항목과 §17.5b가 부딪히는 지점이 있습니다.**
> "달성 전제"를 "판정하지 않는다"로 읽으면 **쉬는 것이 공짜**가 되어 §17.5b의
> "쉰 달만큼 진척이 없고 그게 곧 실패 위험"이 성립하지 않습니다.
> 그래서 수집·발견의 진척을 **`강도 × 일한 달 / 기간`** 으로 두었습니다 —
> **기간을 전부 일하면 정확히 닿고, 한 달이라도 쉬면 못 닿습니다.**
> 근거: `docs/08` #38. **다만 이것은 수집·발견에만 답을 줍니다** —
> 지킴형은 진척을 안 보므로 휴식이 여전히 공짜이고, 토벌형은 처치 수를 세므로
> 별개 문제입니다(`docs/08` #42). **어느 쪽도 주인님이 정한 것이 아닙니다.**
> **지킴형 예외** — 습격이 안 오면 진척 0인데 그게 성공이므로 진척을 안 봅니다 (§17.3 근거).

그래서 판단이 옮겨갑니다 — **"채울 수 있나"가 아니라 "버틸 수 있나".**
HP가 남을까, 포션이 모자라지 않을까, 피로가 쌓여 후반에 무너지지 않을까.

> **부작용 하나:** 아슬아슬한 성공과 여유로운 성공이 같은 값이라, 과잉 전력을 보내는 게
> 항상 유리해집니다. 이를 막는 건 규칙이 아니라 **달력**입니다 — 다섯을 보내면
> 그 다섯의 그 기간이 잠기고, 그 사이에 뜬 의뢰는 못 받습니다.
> **기회비용이 유일한 브레이크입니다.**

1년짜리는 그 사람의 12칸을 전부 잠급니다. **그 해엔 육성을 못 합니다.**

### 17.5 진행 — 누가 무엇을 하는가

| 누가 | 무엇을 |
|---|---|
| **플레이어** | 누구를 보낼지, 무엇을 지원할지 — **편성과 보급** |
| **모험가 AI** | 조우 판단, 전투, 견적이 안 나오면 후퇴 — **실행** |
| **주인공** (동행 시) | 그 실행에 끼어들기 |

- 기간 동안 **조우 확률**로 마물을 만나고, 만나면 전투합니다.
- **주인공이 동행하면 전투를 보고 개입할 수 있고, 없으면 백그라운드로 처리**됩니다.
- **모험가는 생존을 최우선**으로 행동합니다. 호위 의뢰에서는 **호위 대상 보호가 최우선**입니다.
- 보호와 생존 기준으로 클리어 견적이 안 나오면 **최대한 빨리 후퇴**합니다. 그 경우 실패입니다.

### 17.5b 자원은 파견 단위 · 자연회복이 있습니다 [확정]

**HP와 마나 둘 다 파견 내내 이어지고, 자연회복이 있습니다.**

> ⚠️ 지금 코드는 **마나만 매 전투 리셋**됩니다. 전투 시작 시 만땅이고 회복 수단이
> 전혀 없습니다(`SpendMana`만 있음). HP·회복약과 결이 안 맞고, 매 전투 채워지면
> 사실상 마구잡이로 쓰는 것과 같아집니다. 고쳐야 합니다.

파견 중 **휴식하는 달**에는 50~100%까지 회복해도 됩니다. **의뢰 기간이 고정이고
성공/실패가 이분법**이라(§17.4), 쉬는 달만큼 진척이 없고 그게 곧 실패 위험이므로
회복이 후해도 공짜가 되지 않습니다. 오히려 회복이 짜면 "다쳤으니 접자"가 되어
중도 이탈만 늘어납니다.

**[검토중]** 자연회복 속도 · 휴식 회복량의 정확한 수치.

### 17.6 보급

길드가 파티에 **포션·장비를 지원**할 수 있습니다.
단 **그 파티가 들 수 있는 짐 수량 한도 내에서만** 가능합니다.

짐꾼의 **가방**이 여기서 처음으로 실질적 의미를 갖습니다 —
포션을 더 들려 보내고 싶어도 들 사람이 없으면 못 보냅니다.

> `SupportSkill.Portering`은 폐기됐습니다 (§16.8c). 적재량은 **가방이라는 물건**에서
> 나옵니다 — `Supplies.CapacityOf` = 1인당 기본 지참량 + 든 가방의 적재량.
> 기본 지참량이 0이면 짐꾼이 사실상 필수가 되어 "짐꾼 최대 1명"과 솔로잉이
> 무의미해지므로, 기존 기본값 2를 그대로 1인당 지참량으로 씁니다.

### 17.7 중도 이탈

- **가능합니다.** 3달 의뢰를 1달 채우고 빠질 수 있습니다.
- **실패는 실패입니다.** 그래도 빼는 이유는 **손절**입니다 —
  끝까지 밀어서 무너지느냐, 빈손이라도 사람을 지키느냐.
- 빠진 직후 **바로 다음 의뢰가 가능한지는 별개**입니다. 휴식이 필요할 수 있습니다.
  (주인님 원문: "물론 이 시점에서 파티가 바로 다음 의뢰가 가능할지 그거는 별개의
  이야기라고 생각합니다만.. 휴식이 필요할지" — **가능성으로 남겨둔 것**입니다.)

그래서 달력 잠금은 **구속이 아니라 예약**입니다. 빠지면 칸이 풀립니다.

> ⚠️ 여기에 한때 이렇게 적혀 있었습니다 — *"실질적인 브레이크는 규칙이 아니라 몸 상태.
> 지쳐서 돌아온 파티는 칸이 비어도 못 나갑니다. 훈련 쪽 피로 시스템이 그대로 이어지므로
> 따로 만들 것이 없습니다."* **전부 에이전트가 쓴 문장입니다.** 주인님이 말한 것은
> "휴식이 필요할지"라는 **가능성 한 줄**뿐이고, 파견 피로라는 시스템도 그것이
> 유일한 브레이크라는 규정도 없었습니다.
>
> 그 문장 때문에 에이전트가 "§17.7이 유일한 브레이크로 지목했으므로 파견 피로를
> 새로 만들어야 한다"는 **없던 요구사항**을 만들어 냈습니다.

### 17.8 발생 — 랜덤

- **랜덤으로 발생합니다.** 고정된 개수는 없습니다.
- **길드 랭크가 양과 질을 동시에 조절**합니다. 랭크가 오르면 뜨는 확률이 늘고
  더 높은 레벨의 의뢰가 나옵니다. 낮은 랭크에서는 낮은 레벨이 많이 뜹니다.
- **감당 못 할 의뢰는 아예 뜨지 않습니다.** 그래서 랭크 상승의 체감이
  **"새로운 게 보이기 시작한다"** 로 옵니다.
- **그 달에 수락하지 않으면 사라집니다.** 쌓아두고 고를 수 없습니다.
  단 **전개상 필수 의뢰는 유지되는 형태가 있을 수 있습니다.**
- **동시 진행 상한 없음.** 모험가 전원을 실전에 투입해도 됩니다.
  대신 성장이 막혀 상위 의뢰를 받기 어려워집니다 — **규칙이 아니라 성장 압력으로 조절합니다.**

이 둘(사라짐 + 상한 없음)이 맞물려 매달 같은 질문이 걸립니다.

> **지금 벌 것인가, 나중을 위해 키울 것인가.**

좋은 의뢰가 떴는데 사람이 전부 훈련 중이면 그냥 놓칩니다.
국가 지원 5년이 끝나는 시점이 이 압력을 실제로 조입니다.

### 17.9 계절 — 확률 가중치일 뿐

**1월 시작, 3개월씩 4계절** (1~3월 봄 … 12월 겨울).

> ⚠️ **계절은 강제가 아닙니다.** "이 계절엔 훈련만" "이 계절엔 실전만" 같은 개념이
> 아닙니다. 훈련이냐 실전이냐는 **항상 열려 있는 선택**이고, 계절은 의뢰 풀의
> 경향만 바꿉니다. 확정 규칙으로 두면 플레이어가 계절표를 외워 최적화합니다.

| 계절 | 경향 |
|---|---|
| **봄** | 월동에서 깬 마물이 많음. 농사 준비 보호, 마을 보수공사 |
| **여름** | 마물 활동이 상대적으로 잠잠. 보수 계열이 많음 |
| **가을** | 수확 지원, 월동 대책 준비, 채집 |
| **겨울** | **[검토중]** — 굶주린 마물이 내려온다는 해석도, 내부 보수공사도 가능 |

채집은 사계절 다 있을 수 있습니다. 여름이라고 마물이 아예 없는 것도 아닙니다.

**마을 규모가 커지면 의뢰 풀이 넓어집니다.** 광산이 열리면 광부 의뢰가 생기는 식입니다.
길드가 던전을 정리 → 그 자리가 광산이 됨 → 광부 의뢰가 생김 — **의뢰가 뽑히는 게
아니라 플레이어가 만든 것**이 되고, 길드만이 아니라 마을도 같이 큽니다.

**갑작스러운 레이드 이벤트** — 거대 마물 출현. 매달 정하는 구조라 미리 계획하지 않으니
갑자기 뜨는 게 부담이 아니라 사건이 됩니다.

### 17.10 연 구조

- 매년 **1월에 길드원 모집**이 열립니다.
- **길드 랭크에 따라 최대 인원**이 정해집니다 (F 8명 / E 15명 / D 25명 — **[검토중]** 실제 수치는
  루즈함과 밸런스를 보고 조절). 직원은 별도로 셉니다.
- **매달 정책을 정합니다.** 연초에 1년치를 한 번에 짜는 방식은 **폐기** —
  말이 안 되는 방향으로 갈 가능성이 높습니다.

### 17.11 [검토중] 남은 것

| 무엇 | 왜 미뤘나 |
|---|---|
| 겨울의 성격 | 위 §17.9 |
| **후퇴가 항상 성공하는가** | 늘 안전하게 빠지면 실패의 무게가 가벼워짐. 후퇴 중 부상·낙오가 있어야 "무리하지 말자"가 판단이 됨 |
| 실패 페널티 (보수 0 외) | 평판·부상·사망 범위. 상태이상·지휘 논의와 같이 봄 |
| 보수 액수 | 경제 구조(§7) 논의에서 |
| 발견형의 결과가 어떻게 남는가 | 던전 발견이 자산이 되는 방식. 마을 성장과 함께 봄 |

| 연초에 그 해 의뢰 일괄 공개 | **매달 정책** (§17.10). 루즈함은 계획이 아니라 자동방침으로 막습니다 |
| 계약 / 상시 / 긴급 2층 구조 | **랭크 기반 랜덤 발생** (§17.8) |
| 계절별 역할 배정 (여름=길드 활동, 겨울=훈련) | **계절은 확률 가중치일 뿐** (§17.9). 역할 배정은 강제로 읽힙니다 |
| 수량형은 조기 종료 가능 | **기간 고정** (§17.4) |

## 15. 연 달력 — 육성과 실전을 한 달력에

> ⚠️ **[01-game-design.md](01-game-design.md) §5.5를 대체합니다.**
> 거기에는 "실전 연도는 월 단위로 쪼개지 않고 결과만 봅니다"라고 적혀 있습니다.
> 육성과 실전을 한 달력에 섞으므로 성립하지 않습니다. 구현 시 그 문장을 지웁니다.

**[확정]** 매달 정책을 정합니다 — 연초에 1년치를 일괄로 짜는 방식은 폐기했습니다(§17.10).
**[확정]** 달력 잠금은 구속이 아니라 예약입니다 — 중도 이탈이 가능하고, 실질적 브레이크는
피로입니다(§17.7).
아래 나머지는 주인님 구상이지만 **"이렇게 하면은.. 어떤가요?"로 끝났고 확정 절차가 없었습니다.**

### 구조

**1년을 12개월로 쪼개고, 육성과 실전 투입을 같은 달력에서 진행합니다.**
지금은 "훈련하는 해"와 "파견 나가는 해"가 분리돼 있는데, 그걸 없앱니다.

```
「올해의 운영방침을 설정해주세요」
  └ 길드원 리스트가 가로로 정렬
      └ 한 명씩 골라 수동방침 / 자동방침 선택
```

**수동방침일 때 월마다 3지선다** — 훈련 · 의뢰 · 휴식.

### 동행 잠금 — 이 구상의 핵심

의뢰 중에는 **특정 멤버와 같이 가는 것**이 있습니다. 동행자를 지정하면
**그 멤버의 그 달도 의뢰로 잠깁니다.** 그 멤버는 나머지 달만 편성할 수 있습니다.

여기서 두 가지가 따라옵니다.

- **자동화 로직이 잠긴 칸을 전제로 계획해야 합니다.** 그 달에 의뢰가 있다는 걸 모르고
  피로를 쌓아두면, 정작 의뢰 달에 지친 상태로 나갑니다.
- **의뢰 선택에 진짜 대가가 생깁니다.** 남의 달력을 잡아먹기 때문입니다.

### 기간

의뢰는 **1달이 기본이지만 2~3달짜리도 있어야** 합니다.

### 주인공

**몸이 하나이므로 한 번에 하나의 의뢰에만 동행합니다.** (수동 지시 가능)

### 파티 조건 완화

지금 §6은 **3년 동행**을 파티 인정 조건으로 두고 있는데, 달력이 생기면
**"함께 나간 달의 합"** 으로 셀 수 있으므로 완화 가능합니다.
**1년으로 할지 반년으로 할지는 [검토중]** — 주인님 표현 그대로 "고민".

### 왜 이 구조가 유력한가

입력 횟수가 **연 15회 안팎**에 들어옵니다. 주인님의 걱정이
"달달이 전부 선택하면 게임이 너무 루즈해지지 않을지"였는데, 자동방침으로
대부분을 넘기고 애착 있는 캐릭터만 손으로 잡으면 그 안에 들어옵니다.

### [검토중] 미결

- 파티 인정 기간 — 1년 / 반년
- 자동방침이 잠긴 칸을 어떻게 계산하는가 (규칙 미정)
- `FieldYearSession`(12개월 = 의뢰 1건)을 어떻게 대체하는가

### §17로 해결된 것

- ~~의뢰 공개 시점~~ → **매달 뜨고, 그 달에 안 받으면 사라짐** (§17.8)
- ~~기간 단위~~ → **1~3달, 1년도 있음. 고정** (§17.4)
- ~~한 달에 몇 개~~ → **상한 없음. 성장 압력으로 조절** (§17.8)

## 11. 주인공 — 보류

불로불사 vs 세대 계승. **게임이 더 구체화된 뒤 결정합니다.**

세대 계승 쪽의 기계적 이점만 적어둡니다.

- **무기한 게임의 압박 문제를 자연스럽게 풉니다.** 마스터에게 수명이 있으면
  하드 타이머 없이도 "내 대에 볼 수 있을까"가 생깁니다
- **은퇴·멘토 시스템이 두 번째 쓰임새를 얻습니다.** 다음 마스터를 은퇴한 모험가 중에서 고르면,
  15세에 뽑아 20년 키우고 은퇴시킨 그 캐릭터가 길드를 물려받습니다.
  **애착은 그림이 아니라 기억에서 나온다**는 설계 기둥과 정확히 맞습니다

불로불사로 가더라도 **"왜 불로불사인가"는 풀지 않는 것**을 권합니다.
설명 없는 분위기면 헌장 안이지만, 이유를 서사로 풀면 §4의 "본격 서사 금지"를 넘습니다.

## 12. 구현 순서

의존 관계가 실제로 있습니다. **순서를 잘못 잡으면 두 번 짓습니다.**

```
[2] 훈련 재설계 ─┬─→ [기술 훈련이 숙련도를 올림] ─→ [10] 스킬 해금
                 └─→ [3] 실패 등급 · 부상 제거

[4] 999 하드캡 ──→ [5] 명중·회피·치명타 공식 ──→ [적 생성 재설계]
                                               └─→ [밸런스 재측정]

[6] 파티 시스템 ─┬─→ [7] 경제 구조 (분배율이 파티 등급에 의존)
                 └─→ [8] 계약 구조 (파티 단위 수주)

[9] 장비 최소 ───→ [1] 튜토리얼
[1] 튜토리얼 ←─── [2][6][8] 전부 필요
```

### 권장 순서

| 단계 | 내용 | 왜 여기인가 |
|---|---|---|
| **1** | 훈련 재설계 (§2, §3) | 숙련도가 선택 대상이 되어야 나머지가 성립 |
| **2** | 능력치 스케일 + 전투 공식 (§4, §5) | 적 생성과 밸런스의 전제 |
| **3** | 적 생성 재설계 + 밸런스 재측정 | 공식이 바뀌면 반드시 따라와야 함 |
| **4** | 파티 시스템 (§6) | 계약·경제의 전제 |
| **5** | 경제 구조 (§7) | 파티 등급이 있어야 분배율이 정해짐 |
| **6** | 계약 구조 다전투 (§8) | 파티가 있어야 의미 |
| **7** | 장비 최소 + 튜토리얼 (§9, §1) | 앞의 전부가 있어야 완성됨 |

**튜토리얼이 마지막입니다.** 가르칠 시스템이 다 만들어진 뒤에 만드는 게 맞습니다.

### 일정에 대한 솔직한 말

`docs/06-roadmap.md`는 오늘 내용을 모르는 상태에서 쓴 것이라 **무효에 가깝습니다.**

훈련 시스템 재설계와 전투 공식 교체만으로도 이전에 잡은 "1주차" 분량을 크게 넘습니다.
**7단계 전부를 콘솔로 완성하는 데는 몇 주가 걸립니다.**

각 단계가 끝날 때마다 돌려볼 수 있게 만들어서, 중간에 방향을 바꿀 수 있게 하겠습니다.

## 19. 평가서 제거 · 첫 캐릭터 평범형 (2026-07-30)

**[확정]** 평가서(영입 시 추정 잠재력·개화·기질·적성 표시) 시스템을 **뺀다.**
캐릭터마다 개별 평가서를 손으로 만들 계획이 없는 한, 일괄 생성 추정치는 넣지 않는다.
영입 화면에는 지금의 능력치와 희망 직업만 보인다. 성장 곡선은 키워 봐야 안다.

**[확정]** 튜토리얼 고정 캐릭터는 대기만성형이 아니라 **평범한 성장형**으로 한다.

이 결정으로 §1의 두 항목이 대체된다 (아래 §1에 상태 표시):
- "진실 공개 — 평가서와 실제를 대조" 장면: 평가서가 없으므로 성립하지 않는다
- "반드시 틀리는 성장 곡선을 심은 고정 캐릭터": 평범형으로 바뀐다

이해도(§16.7 — 시간과 함께 숨겨진 것이 드러나는 장치)는 그대로 확정으로 남는다.
평가서 없이 시작하는 지금 상태가 오히려 이해도의 출발점("아무것도 모른다")과 맞는다.

## 20. 다음 단계 스코프 (2026-07-30)

콘솔의 표현 한계를 계기로 다음 단계의 범위를 논의해 정했다. 일곱 갈래다 —
수동 전투 · 행동 횟수 · 길드 자원과 상점 · 의뢰 F~E급 4종 · 직업 전사만 오픈 ·
태생 패시브 · 초급 아이템 — 그리고 UI 프로토타입 방향이 하나 더 있다.

### 20.1 수동 전투 — §14를 대체한다

**[확정]** 주인공이 동행한 파티의 전투는 **플레이어가 직접 조작한다.**
행동을 고르고 **스킬도 직접 선택해서 쓴다.**

이것이 원래 의도였다. "자동 전투가 돌고 플레이어는 지시로 끼어든다"(§14, 01 §4.4)는
에이전트의 축소 해석이었고, 사람이 결정한 적이 없다. §14는 [대체됨]으로 표시한다.

바뀌지 않는 것:
- **동행하지 않은 파견의 전투는 자동**이다. 전술 규칙(`조건 → 행동`)과 판단력은
  여기서 그대로 산다. 배치 시뮬레이션도 자동 전투로 돈다 — 결정론(01 §8)은 유지된다.
  수동 조작도 입력이므로, 같은 시드 + 같은 입력 → 같은 결과라는 원칙과 충돌하지 않는다.
- 조작도 스킬·무기·쿨다운·마나 조건을 지켜야 하고, 검사는 UI가 아니라 코어가 한다.
- 지시 불통 기전(§18.7 — 공포·혼란)은 유지된다. 수동 모드에서는 "그 아군에게 조작이
  닿지 않는다"로 나타난다.

**[검토중]** 수동 전투의 턴 구조 · 화면 흐름. 헌장 서두의 "직접 싸우지는 않는다"는
이 결정에 맞춰 고쳤다(길드장이 모험가로서 싸우지 않는다는 뜻이었고, 전투 조작과는 다른
이야기다).

### 20.2 행동 횟수

**[확정]** 파견지(위치한 마을)에 따라 **한 달 안에서 쓸 수 있는 행동 횟수**가 정해진다.
하위 수준 지역은 **최대 3회**다. 주인공이 컨트롤하는 파티는 이 횟수 안에 의뢰 목표를
달성해야 한다.

**[검토중]** 무엇이 1회를 소모하는가(전투 · 작업 · 이동의 구분) · 동행하지 않은
자동 파견에도 같은 횟수를 적용하는가.

### 20.3 길드 자원 · 상점

**[확정]** 길드 자원은 평판(명성) · 자금 · 유지비다. **상점**이 생긴다 —
**약국**에서 포션을, **대장간**에서 무기를 산다.

**[방향]** 유지비의 구성은 식비와 보수비로 본다. 기존 §7과 대응된다 —
식비 = 1인당 정액 유지비, 보수비 = 보수 분배(모험가 몫 30~60%). §7은 유지된다.

**[방향]** 은퇴한 모험가가 제조 스킬(포션 제조 · 대장장이)을 갖고 있으면, 이후에는
그들에게 부탁해 포션과 무기를 만들 수 있다. 이때 **재료 아이템**이 필요해진다.

**[제안]** 장비 구매·수리비를 지출 항목으로 넣는다. 상점이 생기면 자금을 쓸 곳이 생겨,
측정된 "5년 순손실인데 파산 압박이 없다" 문제(08 #66)와 맞물린다. 승인된 적 없다.

### 20.4 의뢰 — 당장은 F~E급 4종

**[확정]** 지금 넣는 의뢰는 F~E급 수준 4종이다.

| 의뢰 | 구조 |
|---|---|
| **마을 앞 고블린 토벌** | "한 달 동안 고블린으로부터 마을을 지켜라." 수동 모드에서는 고블린 셋과 전투 |
| **상인 호위** | 옆 마을까지 상인 이동, 가도 호위. 산적·고블린 랜덤 인카운터 |
| **약초 채집 호위** | 상인 호위와 같은 구조 |
| **마을 보수공사** | 인카운터 확률 낮음. **도움역**과 **호위역**으로 나뉜다 |

보수공사의 역할 분리: 도움역은 실제 공사를 도우며 근력·지구력이 자라고, 호위역은
평소에는 지구력·기교 계열이 자라다가 마물이 나오면 무기 숙련이 오른다.
(어느 능력치인지는 열려 있다 — 사람이 "다른 스탯도 괜찮다"고 했다.)

**[확정]** 의뢰는 지금처럼 무작위로 생성한다. 보수도 무작위여도 된다.
§17(의뢰 형태 4종 판정)은 그대로다 — 이 4종은 그 형태 위의 구체 내용이다.

### 20.5 직업 — 전사만 오픈

**[확정]** 당장 여는 직업은 **전사 하나**다(한손검 + 방패 조합). 거기에 맞는 스킬
구성은 **사람이 이후에 정리한다.** 다른 직업은 잠근다 — §16의 직업 체계 자체는
유지되고, 오픈 순서만 제한된다. 직업은 순차적으로 연다.

### 20.6 태생 패시브 — 캐릭터 생성의 핵심

**[확정]** 성장 곡선과 무기 적성을 빼면, 캐릭터 무작위 생성의 개성은
**태생 패시브를 몇 개 받고 태어나는가**와 **그 패시브가 언제 해금되는가**에서 나온다.

**[방향]** 기본 2~3개, 붙는 것이 많으면 6~8개까지. 개수와 내용은 플레이어에게
알려지지 않은 느낌으로 두고, 키우는 동안(숙련 등과 맞물려) 드러난다.

**[검토중]** 개수 분포의 정확한 값 · 해금 조건의 설계.

### 20.7 초급 아이템

**[확정]** 지금 해금하는 아이템은 초급만이다.

- 무기 6종: **나무검 · 나무방패 · 철검 · 철방패 · 강철검 · 강철방패**
- 소모품: **체력 포션(소) · 마나 포션(소)**

**[방향]** 몬스터별 전리품은 어떤 몬스터를 만드는지 정할 때 함께 정한다.
재료 아이템은 은퇴자 제작(§20.3)을 넣을 때 같이 들어온다. §9(장비·포션 최소)의
"최소"가 이 목록으로 구체화된 것이다.

### 20.8 UI — HTML 웹 스타일 프로토타입

**[방향]** 콘솔은 의도가 전달되지 않아, 웹게임처럼 HTML로 실제 게임 화면 느낌의
프로토타입을 만든다. 이미지가 들어갈 부분은 쳐내고 **UI 구조 위주**로 한다.
앞으로 게임을 만들 때의 참고 설계도로 삼는다. 엔진 선택(M2)을 대체하지 않는다.

**[제안]** 구현은 Blazor WASM으로 한다 — 코어가 C#이라 브라우저에서 그대로 돌고,
게임 로직을 JS로 다시 쓸 필요가 없다. 승인된 적 없다.

## 21. UI 화면 구조 — 와이어프레임 승인 (2026-07-30)

§20.8의 방향을 와이어프레임으로 그려 세 번 고친 끝에 승인받았다.
그림 자체가 기준이다 — [design/ui-wireframe.html](design/ui-wireframe.html) (브라우저로 연다).

### 21.1 해상도

**[확정]** 기준 해상도 **1920×1080, 16:9 고정 + 레터박스**.
최소 검증 해상도 1280×800(Steam Deck) — 본문 글자는 1080p 기준 24px 아래로 내리지 않는다.

### 21.2 화면 흐름과 구조

**[확정]** 다음 구조로 간다.

```
타이틀 (키아트 배경 · 새로 시작/이어하기/설정/종료)
  → 오프닝 (정적 삽화 + 내레이션 · 길드명 입력) → 튜토리얼 선택
  → 메인 (월 루프의 축)
```

- **메인**: 상단 자원바(길드명·랭크 / 년월·계절 / 자금·명성·단원) · 사무실 배경과 단원
  스탠딩 · 소식 패널 · **푸터 아이콘 버튼 4개(캐릭터 · 길드 · 의뢰 · 시스템) + 맨 오른쪽
  업무 시작**
- **업무 준비**: 3단 — 왼쪽 캐릭터 리스트(초상화+이름 버튼) / 가운데 육성·의뢰 탭에서
  행동 선택 / 오른쪽 캐릭터 정보. 배정하면 캐릭터에 ✓ 표시. **자유로운 단원 전원을
  배정해야 업무 시작이 활성화**된다. 파견 중인 단원은 잠김으로 표시되고 배정에서 빠진다
- **업무 시작** → 한 달 진행(동행 파견의 전투는 수동 전투 화면 경유) → **월 결과 리포트**
  (캐릭터별 성장·교전 경과) → 다음 달 메인
- **수동 전투**: 상단 행동 순서 띠 · 전열/후열 스탠딩 배치 · 하단 명령 패널.
  명령은 메인 푸터와 같은 4분류 — **공격 · 스킬 · 아이템 · 후퇴** — 이고 분류를 고르면
  목록이 펼쳐진다. 후퇴는 확인을 묻고 파견 결과에 "후퇴"로 기록된다.
  이동(전열/후열)·대기는 보조 버튼 (배치가 어색하면 조정한다)
- 푸터 행선지 — 캐릭터: 목록·상세·전직·장비 / 길드: 상점·모집·파티·재정 /
  의뢰: 게시판 열람 / 시스템: 저장·설정·타이틀로

**[확정]** 이미지(키아트 · 초상화 · 스탠딩 · 배경)가 **들어가는 전제**로 레이아웃을 잡는다.

### 21.3 따라오는 것

**[확정]** 타이틀의 "이어하기"가 성립하려면 저장/불러오기가 필요하다.
05-gaps에서 미뤄 둔 직렬화를 프로토타입 단계에서 해제한다 — §20 스코프 구현으로
데이터 스키마가 굳은 뒤가 적기다.
